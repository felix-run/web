Every tool call runs through wrappers composed in `build_agent`. Source: `felix.manifests.builder` in [felix-run/felix](https://github.com/felix-run/felix).

## Stack (call direction)

```
model → Approvals → LLM Judge → Guardrails → Limits
      → Content screen → Command screen → Policies → Secret masking → inner tool
```

Applied innermost-first at build time so the runtime order above holds. Secret masking is **always on**.

Wrappers return **deny strings** via `deny_output` (never throw) so the model can adapt. Outer post-call wrappers must check `is_wrapper_deny` and pass denies through verbatim.

## Layers

| Layer | Manifest | Decision |
|---|---|---|
| **Secret masking** | always | Strip harness credentials from tool output before the model / audit sees them |
| **Policies** | `spec.policies` | Principal must hold all `required_scopes` for matched tools (glob, case-sensitive) |
| **Command screening** | `spec.command_screening` | Pre-call rules over every execution-bearing argument — `command`, `cmd`, `code`, `script`, `stdin`, `argv`, `shell_command`, `args` — and, for `sandbox` / `container` transports, every string argument, since there the payload *is* the program |
| **Content screening** | `spec.content_screening` | Post-call injection classifier on tool results — every untrusted tool, **plus** whatever `tools` names; honours `on_flag` when the screener itself is unavailable |
| **Limits** | `spec.limits` | Cap tool calls, wall clock, peer hops, input/output tokens (absolute ceilings apply) |
| **Guardrails** | `spec.guardrails` | PII-style filters on input/output/(final response); redact or block |
| **LLM judges** | `spec.guardrails.judges` | Score tool (or final) output against criteria; below threshold → deny |
| **Approvals** | `spec.approvals` | Human gate by call signature; Postgres is system of record |

## When a control cannot run

A control that cannot run has not cleared anything, so unavailability is never treated as a pass.

- **The LLM injection screener** is tri-state: flagged, clean, or *unavailable*. A missing key, an
  expired credential, a 429, a provider outage, or a reply whose score cannot be parsed all yield
  unavailable, which honours `content_screening.on_flag` — `block` denies (inbound: `503`),
  `quarantine` replaces the content — and emits `felix_control_unavailable{control="content_screening"}`.
  Marker-based screening still runs regardless of model availability.
- **The PII guardrail** falls back to three regexes (email, US SSN, card-like digit runs) when
  Presidio or its spaCy model is absent. That fallback is announced at `WARNING` with
  `felix_control_degraded{control="pii"}`. Only deterministic outcomes are cached — a *transient*
  engine-init failure retries on next use rather than pinning the process to the regex path.
- **`guardrails.providers`** is a closed set, so a typo is a compile error rather than a manifest
  that reports guardrails enabled while applying no wrapper.

Alert on `felix_control_unavailable` and `felix_control_degraded`: both mean a control named in a
manifest is not the control actually in force.

## Egress

Outbound URLs are checked in two halves, deliberately in different places.

**At parse.** Scheme, plain `http` outside development, internal names and suffixes
(`.svc`, `.cluster.local`, `.internal`, `metadata.google.internal`), and IP literals —
including the decimal form `http://2130706433/`, which is `127.0.0.1` to a resolver but not an
IP literal to `ipaddress`. None of this needs DNS. Resolving here used to run a blocking
`getaddrinfo` inside a pydantic validator, on the API event loop, once per ref on every
manifest read *and* write.

**At dial.** The address check. `felix.security.egress` supplies an httpx transport whose
network backend resolves once, validates every returned address, and connects to one of the
addresses it validated. That is the difference between enforcement and advice: resolving in a
guard and letting the client resolve again is two independent lookups, and a name that answers
them differently — DNS rebinding with a short TTL, or a nameserver that simply drops the
guard's query while answering the client's — reaches whatever it likes. One blocked answer
refuses the whole name, so a round-robin containing a private address cannot be reached by
retrying. A lookup that fails or times out refuses the dial, which is safe precisely because
this *is* the connection.

TLS is unaffected: certificate verification and SNI run against the hostname the caller asked
for while the socket goes to the pinned address.

`proxy`, `mounts` and `uds` are refused rather than ignored, since each chooses a destination
the guard never sees. Supplying a transport also disables httpx's environment proxies, so
`HTTP_PROXY` and `HTTPS_PROXY` do **not** apply to these calls — worth knowing if your egress
containment is a proxy allowlist.

### The browser is a partial exception

`spec.browser_tools` hands its URL to Chromium, which resolves for itself. The navigation host
*is* pinned — the browser launches with `--host-resolver-rules=MAP <host> <validated address>` —
but cross-host subresources and redirects are checked per request without being pinned, because
denying them outright breaks any page that loads assets from a CDN. This is the only outbound
path where the URL comes from the model rather than a manifest, so treat a page's cross-host
assets as reaching whatever they resolve to at load time.

## Limits state

`LimitState` lives on `RequestContext` (contextvars): tool-call / peer-hop counters, wall-clock abort, cumulative tokens, audit count. Patterns check token budgets before each model call; the limits wrapper checks wall clock / tool calls / peer hops before each tool invoke. Thread `ctx.signal` through outbound HTTP so wall-clock aborts cancel in-flight work.

## Approvals

1. Canonicalize args → SHA-256 call signature (optionally bound to principal).
2. Lookup / insert `pending` row; return `[approval required] …` to the model.
3. Operator decides via `POST /approvals/{id}/decide`.
4. Retry with same args finds `approved` / `denied` / still `pending`.

Unattended runs (scheduler, eval replay) refuse approval-gated tools unless `allow_unattended: true`. TTL / one-shot options bound standing grants.

## Fatal tools

`fatal=True` on a tool aborts the loop with the error as the final message (no model recovery). Use sparingly — quotas, hard security failures, unusable config.

:::tip
Tool targeting for policies, approvals, judges and `content_screening.tools` matches by glob
(`fnmatch`, case-sensitive) so MCP tools named `server__*` stay gated even if the remote renames
suffixes. Patterns match in any position — `github__*`, `*__search`, `mcp__*__write`, `*`.

A pattern that matches no bound tool is logged at WARNING and counted as
`felix_rule_targets_nothing` at compile time. It is not refused: an MCP server whose discovery
failed binds no tools, and refusing would let a remote outage take the agent down with it. Check
that counter after adding a rule — a rule targeting nothing is a control that validates and
enforces nothing.

`spec.policies` and `spec.approvals` are capped at 64 rules each — matching is O(rules × tools)
and a manifest is compiled per request.
:::

## Targeting, precedence, and who can hold a scope

`content_screening.tools` is **additive**. Screening covers every untrusted tool — anything
whose transport is not `local`, plus anything sourced from `mcp:`, `peer:`, `a2a:` or `queue:`
— and, in addition, whatever `tools` names. Naming a trusted local tool extends screening to
it; it cannot narrow screening away from anything. There is deliberately no way to turn
screening off for an untrusted tool, because that is the thing screening exists to prevent.
For cost, the levers are `content_screening.model` and `on_flag`.

Approvals is the only control that selects *one* rule — policies and judges apply every match,
so for them more matches only tighten. When several approval rules match a tool, a rule naming
it **literally** wins over one matching by pattern, and among equals the last declared wins.
That makes glob targeting non-weakening: a pattern can only gate a tool nothing gated before,
and never displaces a stricter literal rule.

### Policies need a caller who can hold a scope

`apply_policies` denies when a required scope is absent — "no scopes" must not read as "all
scopes". Several contexts carry an empty scope set by construction, and in those a policied
tool always denies:

- durable fibers (principal `fiber`), scheduled jobs (`cron`), and `felix eval`
- `FELIX_AUTH_MODE=none`, which is what `make dev` sets

`manifests/governed.yaml` policies `calculator` on `tools:calc`, so it denies its own
calculator under `make dev`. Mint a token carrying the scope rather than removing the policy.
A manifest in this shape is named at compile with a WARNING and `felix_policy_unsatisfiable`.

Policy scopes are matched literally: the `admin` / `*` bypass and the `x:write` implies
`x:read` rule that the management API applies do **not** apply here.
