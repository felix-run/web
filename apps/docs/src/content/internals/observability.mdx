What Felix emits and where to look. Complements [governance](/internals/governance/). Code: `felix.observability` + `felix.audit` in [felix-run/felix](https://github.com/felix-run/felix).

## Signal paths

| Path | Sink |
|---|---|
| **Counters / histograms** | Prometheus (`record_counter` / `record_histogram`); scrape `/metrics` |
| **Spans** | In-process + optional OTLP when `FELIX_OTEL_ENABLED=true` (`uv sync --extra otel`) |
| **Audit events** | Buffered → Postgres `audit_events` (worker flush); query via `GET /audit` |

:::tip
**Counters are the alert signal.** Audit rows are the trail after a threshold trips.
:::

## Useful counters

Names are `orchestrator_*` (stable across the port from the old harness):

| Counter | Meaning |
|---|---|
| `orchestrator_tool_calls` | Per tool dispatch (`transport`, `status`, `manifest_id`) |
| `orchestrator_tokens` | Per model call (`kind` ∈ input/output/cache_*) |
| `orchestrator_policy_decisions` | Scope denies |
| `orchestrator_limit_breaches` | Cap hit (`max_tool_calls`, wall clock, tokens, …) |
| `orchestrator_guardrail_blocks` / `orchestrator_judge_*` | Filter / judge outcomes |
| `orchestrator_approval_requests` / `_decisions` | Human gates (`denied_unattended` for background) |
| `orchestrator_model_switches` | Fallback or confidence escalation |
| `orchestrator_anomalies` / `_auto_rollbacks` | Error-rate scan vs EWMA; canary weight → 0 |
| `orchestrator_unhandled_error` | API error boundary — **should be zero** |

Governance counters keep the inner tool `transport` (`local` / `mcp` / `a2a` / `container` / `queue` / `sandbox` / `browser`) through `wrap_executor`.

## Audit events

Every row: `tenant_id`, `ts`, `event_type`, `manifest_id`, `principal_subj`, `status`, `payload_json`. Common types:

`tool_call`, `policy_decision`, `limit_exceeded`, `guardrail_block`, `judge_score`, `approval_request` / `approval_decision`, `plan_step`, `job_run`, `manifest_*`, `anomaly_detected`, `auto_rollback`, `model_switch`, `unhandled_error`.

Payloads are secret-redacted before persist. Per-request audit caps drop excess events (with a truncation marker) so a runaway loop cannot flood storage.

Optional warehouse spill (`FELIX_WAREHOUSE`) copies audit/eval analytics after Postgres write — Postgres stays authoritative.

## Incident walk

1. `GET /audit?tenant=…&manifest_id=…` — timeline by `event_type` / `status`.
2. Find failing `tool_call` → `payload.tool` + `transport`.
3. Confirm with Prometheus rate for that `manifest_id`.
4. For durable chats, poll `GET /chat/runs/{resume_token}` and inspect fiber/run status.

## Local

`make up` / `make dev` → hit `/metrics` and `/audit`. Enable OTLP against a local collector when debugging cross-service latency. Deploy guidance: [deploy](/guide/deploy/).
