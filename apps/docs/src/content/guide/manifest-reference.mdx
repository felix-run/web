Every field in the `apiVersion: felix/v1` manifest schema. Source of truth:
[`packages/harness/src/felix/manifests/schema.py`](https://github.com/felix-run/felix/blob/main/packages/harness/src/felix/manifests/schema.py),
plus the compile-time rules in `manifests/governance.py` and the binders in `manifests/builder.py`.

Every model is Pydantic v2 with `extra="forbid"`, so an unknown key is a hard parse error — not a
warning. Where a field has a default, the default is what you get if you omit it.

## Top-level shape

```yaml
apiVersion: felix/v1   # default; only this exact value is accepted
kind: Agent            # default; only this exact value is accepted
metadata: { ... }      # required
spec: { ... }          # defaults to a minimal react agent
```

Validate one without starting the stack:

```bash
uv run felix validate-manifest manifests/quick.yaml
uv run felix validate-manifest manifests/governed.yaml -e production   # applies production rules
```

## `metadata`

| Field | Type | Default | Notes |
|---|---|---|---|
| `name` | string, 1–128 chars, `^[a-zA-Z0-9._-]+$` | required | The manifest id, the OpenAI `model` value, the audit `manifest_id`, and an object-store key segment. No slashes or whitespace, so it cannot escape its key prefix. |
| `version` | string | `"1.0.0"` | Free-form. Distinct from the tenant store's monotonic version number. |
| `description` | string | `""` | Surfaced on `GET /v1/models` and the agent card. |
| `tags` | string[] | `[]` | Free-form labels. |
| `starters` | `{title, prompt}[]`, at most 8 | `[]` | Prompts a client offers on an empty thread; `prompt` is sent verbatim when chosen (chat-ui sends it on click; the terminal client's `/start <n>` puts it in the composer first). `title` is 1–60 chars, `prompt` 1–2000. Listed on `GET /v1/models` as `felix.starters`. Presentation only — nothing reads it to decide what a run may do. |
| `greeting` | `{headline, subtitle?}` | none | What a client says on an empty thread, in place of its own default. `headline` is 1–80 chars, `subtitle` 1–300; both plain text, and written for any client rather than one UI. Listed on `GET /v1/models` as `felix.greeting`, `null` when not declared. |

```yaml
metadata:
  name: cowork
  greeting:
    headline: What should we do in this folder?
    subtitle: cowork reads the workspace without asking, and asks before it writes a file or runs a command.
  starters:
    - title: Find TODOs
      prompt: Search the workspace for TODO and summarize the matches by file.
```

## `spec.pattern`

```yaml
spec:
  pattern: react   # default
```

Built-ins: `react`, `deep`, `reflect`, `plan_execute` (single-agent) and `router`, `parallel`,
`groupchat` (multi-agent). The registry is open — `register_pattern(name, builder)` adds more, and
nothing in core enumerates the list. See [Patterns](/internals/patterns/).

Multi-agent patterns require `sub_agents` and reject `peers`, `containers`, `queues`, `sandboxes`
and `browser_tools`; a sub-agent's own leaf manifest declares those instead.

## `spec.model`

```yaml
spec:
  model:
    id: claude-sonnet
    temperature: 0
    max_tokens: 4096
    thinking_level: medium
    fallbacks: [claude-haiku]
```

| Field | Type | Default | Notes |
|---|---|---|---|
| `id` | string \| null | `null` | Logical route name. Null falls back to `FELIX_DEFAULT_MODEL_ID` (`claude-sonnet`). |
| `temperature` | float | `0.0` | |
| `max_tokens` | int \| null | `null` | Provider default when unset. |
| `cache` | bool | `false` | Provider prompt caching. |
| `thinking_budget` | int \| null, `128`–`64000` | `null` | Extended-thinking token budget. |
| `thinking_level` | `off` `minimal` `low` `medium` `high` `xhigh` `max` \| null | `null` | When set, **overrides** `thinking_budget` via the level map. |
| `fallbacks` | string[] | `[]` | Tried in order on a provider error; increments the `felix_model_switch` counter. The vision route tries the ones that can see. A turn a fallback answers is metered at the fallback's rates. |
| `vision_model` | string \| null | `null` | Route for any call carrying an image when `id` is a text-only model. Null falls back to `FELIX_DEFAULT_VISION_MODEL_ID`; with neither, such a turn is a 422. See [Images and text-only routes](/internals/model-client/#images-and-text-only-routes). |
| `confidence_escalation` | object | disabled | See below. |
| `price` | map[string, float] | `{}` | USD per 1M tokens, overriding the built-in table for cost attribution. |

Logical ids resolve through `DEFAULT_MODEL_ROUTES`, overridable with `FELIX_MODEL_ROUTES`:
`claude-opus`, `claude-sonnet`, `claude-haiku`, `claude-fable`, `gpt-4.1`, `gpt-4.1-mini`,
`llama-3-pro`, `llama-3-fast`, and on Workers AI `kimi-k2-cf`, `gpt-oss-120b-cf`, `gpt-oss-20b-cf`,
`glm-flash-cf`. The suffixed `claude-sonnet-4` and `claude-haiku-4` are retained as
legacy aliases onto the current model in the same tier; prefer the unsuffixed ids.
Providers are `anthropic`, `openai`, `ollama`, `workers_ai`, `groq`, `together`, `deepseek`,
`cerebras`, `fireworks`, `openrouter`, `xai`, `mistral` and `google`, plus any registered through
`register_model_provider`. Note that `limits.max_cost_usd` is refused at compile when the resolved
model has no known rates — supply them with `spec.model.price`. See
[Model client](/internals/model-client/).

`confidence_escalation` retries with a stronger model when the answer looks hedged:

| Field | Type | Default |
|---|---|---|
| `enabled` | bool | `false` |
| `escalate_to` | string | `""` |
| `low_confidence_markers` | string[] | `["i am not sure", "i don't know", "i cannot answer", "unclear", "uncertain", "no information"]` |
| `min_response_chars` | int ≥ 0 | `40` |
| `decider` | bool | `false` |

With `decider: true` the markers and length are not consulted: `spec.decider` is asked whether the
reply fully answers the request, and a probability below `spec.decider.min_confidence` escalates. The
heuristic stays as the fallback when the decider errors, and for side requests such as compaction
summaries. Honoured on `react` and `deep` only — elsewhere it is refused at validation.

:::note
A client may override the model mid-session with `POST /chat` `{"model": "..."}`, but only against an
allowlist built from `spec.model.id`, `spec.model.fallbacks`, `FELIX_DEFAULT_MODEL_ID` and the route
table. Anything else is `400 model_not_allowlisted:<id>`.
:::

## `spec.system_prompt`

```yaml
spec:
  system_prompt:
    inline: |
      You are a support agent. Cite the knowledge base.
    soul: false
    base: ""
```

| Field | Type | Default | Notes |
|---|---|---|---|
| `inline` | string | `""` | Written in the manifest. |
| `soul` | bool | `false` | Prepend the tenant's shared "soul" prompt. |
| `base` | string | `""` | Shared preamble. |
| `files` | string[] | `[]` | Keys loaded after base/inline and appended. |
| `system_md` | string \| null | `null` | Key loaded as a **full replacement** (`SYSTEM.md` semantics). |
| `append_system_md` | string \| null | `null` | Key appended after the composed prompt. |
| `include_tool_guidance` | bool | `true` | Append the [tool guidance](#spectool_guidance) section. `false` for a prompt that must be exactly what was written. |

<Aside type="caution">
  All three resolve **only** under `workspace/{tenant}/` — in the object store and,
  when `FELIX_WORKSPACE_ROOT` is set, on disk. A key naming anything else is rewritten
  into your own prefix, and one containing `..` is refused. These fields are writable
  by anyone with `manifests:write`, so they are not a way to reach a shared or another
  tenant's file.

  A bare `AGENTS.md`, `AGENTS.override.md` or `CLAUDE.md` **object** still works as an
  operator-placed layer shared across tenants, and is used only when the tenant has no
  file of its own. The same filename on disk under `FELIX_WORKSPACE_ROOT` is not read:
  that directory is shared and agents can write to it.
</Aside>

Parts are joined with `"\n\n---\n\n"` in the order **soul → base → inline**, then file-sourced parts.
Empty parts are dropped.

## `spec.tools`

A list of built-in tool names.

```yaml
spec:
  tools: [calculator, read_file, write_file, edit_file, search_files, list_dir]
```

| Tool | Args | Notes |
|---|---|---|
| `calculator` | `{expression}` | Safe expression evaluator. |
| `list_dir` | `{path}` | Max 500 entries. |
| `read_file` | `{path, offset, limit}` | Max 512 KB; flags binary files. |
| `write_file` | `{path, content, append}` | Max 512 KB. |
| `edit_file` | `{path, old_string, new_string, replace_all}` | Replaces one exact string, leaving the rest of the file untouched. Max 4 MB file; refuses a match it cannot find, and a match it finds more than once unless `replace_all` is set; refuses when the resulting file would exceed the limit before writing it. |
| `search_files` | `{query, path, regex, max_hits}` | ≤ 50 hits; skips files over 256 KB. |
| `list_skills` / `activate_skill` / `deactivate_skill` / `read_skill_file` | `{name}`; `read_skill_file` also `{path}` | Bound to the real catalog when `spec.skills` or `spec.skill_authoring.enabled` is set; `read_skill_file` is added whenever any skill tool is. |
| `ask_user` | `{question, kind, options, timeout_seconds}` | Asks the person watching the run and waits for the answer. `kind` is `confirm`, `select` (implied by `options`) or `input`; the timeout defaults to 300 s, max 900. Returns `{answered, value}`, or `{answered: false, reason}`. Only a live `/chat/stream` can reach a person, so anywhere else it returns `reason: "no_one_watching"` at once. |

`ask_user` is how an agent puts a decision to a person instead of guessing: both web clients
draw the question as a banner above the composer and post the answer back. Use it for choices that
are genuinely the person's to make. A question nobody can see is no question at all, so the tool
refuses on a non-streaming `POST /chat`, a durable run, `/v1` and A2A rather than holding the run
for its whole timeout.

`edit_file` reads and writes bytes, not text — a universal-newline read would turn every `\r\n` in
a file into `\n`, and writing the result back would rewrite every line ending in a CRLF file the
edit never touched. Use it instead of `write_file` on any file the model did not just create: it is
the only one of the two that cannot lose a byte the model failed to reproduce.

The five workspace tools resolve every path under `FELIX_WORKSPACE_ROOT`, rejecting absolute paths
and any traversal that escapes the root. With the variable unset they fail with
`workspace_root is not configured (set FELIX_WORKSPACE_ROOT)`.

They never follow a symlink. Each path is opened one component at a time from the root with
`O_NOFOLLOW`, so a link anywhere in it — a directory or the file itself — is refused
(`symlinks are not followed in workspace paths`), and a `FELIX_WORKSPACE_ROOT` that is itself a
symlink is refused. Checking a path and then opening it by name would let anything else
writing the workspace swap a directory for a link between the two. `list_dir` reports a link as
`symlink`; `search_files` does not descend into one.

Patterns contribute their own tools: `plan_create` / `plan_update_step` / `plan_get` (`deep`), and
`remember_procedure` when procedural memory is on.

## `spec.tool_guidance`

One line of advice per tool, keyed by tool name or glob, appended to the system prompt under a
**Tool guidance** heading — only for tools the agent actually has once the manifest compiles.

```yaml
spec:
  tool_guidance:
    search: Use `search` to find sources; a result is a title, URL and snippet, not the page.
    fetch: Use `fetch` to read a page before relying on it, and quote what the page says.
    "github__*": Read an issue's comments before proposing a change to it.
```

Advice written into `system_prompt` about a tool outlives the tool: remove `fetch` and the prompt
goes on recommending it. Keyed by tool, the advice goes with the binding. It works for any tool the
manifest binds — built-ins, integration tools, MCP tools by `server__tool` name or glob. Each line
is at most 500 characters; identical lines appear once. A key that matches no bound tool is counted
as `felix_rule_targets_nothing`, like the other tool lists. Tools defined in code (plugins) can
carry their own line, which is listed alongside. Set `system_prompt.include_tool_guidance: false`
to leave the section out.

## `spec.skills`

```yaml
spec:
  skills:
    - name: calculator-help
```

| Field | Type | Default |
|---|---|---|
| `name` | string | required |
| `version` | string \| null | `null` |
| `description` | string \| null | `null` |

A skill is a `SKILL.md` with YAML frontmatter and a Markdown body. The system prompt carries the
catalog — each skill's name and description — and `activate_skill` returns the body to the model as
instructions. `description` here is not read by the loader (the SKILL.md's own frontmatter supplies
the catalog's); it is surfaced on the A2A agent card. `version` pins an operator upload at
`skills/{tenant}/{name}/{version}/SKILL.md`, which then wins over a tenant library skill of the same
name; see [Concepts → Skill](/guide/concepts/#where-skills-come-from) for the full precedence.

| Field | Type | Default | Notes |
|---|---|---|---|
| `spec.skills_declared_only` | bool | `false` | `false` seeds the catalog with every bundled skill, every skill in `FELIX_SKILLS_DIR` and every live tenant-library skill, and `spec.skills` adds to that. `true` makes the declared names the whole catalog. |

## `spec.skill_authoring`

Lets the agent write to its tenant's skill library: binds `create_skill`, `update_skill` and
`submit_skill_feedback`. Off by default.

```yaml
spec:
  skill_authoring:
    enabled: true
    mode: draft
    max_pending: 20
    auto_eval: false
```

| Field | Type | Default | Meaning |
|---|---|---|---|
| `enabled` | bool | `false` | Bind the three tools. |
| `mode` | `draft` \| `publish` | `draft` | `draft`: every save waits for a person to publish it. `publish`: a save is published at once if the publish gate passes, and stays a draft (the result carries `publish_blocked` with the reasons) if not. |
| `max_pending` | int 1–200 | `20` | Undecided agent drafts this manifest may hold in the tenant's library, and undecided feedback it may have filed, before the tools refuse (`pending_cap_reached`, `feedback_cap_reached`). |
| `auto_eval` | bool | `false` | Queue an evaluation (`FELIX_SKILL_EVAL_MODEL`) of every draft the agent saves; the result carries its `eval_id`. Model calls on the tenant's bill. |

**`mode: publish` needs an approval on both writes.** Validation refuses the manifest unless the
approval rule [`spec.approvals`](#specapprovals) would select for `create_skill`, and the one it
would select for `update_skill`, both exist and carry no `when_args` — a conditional rule lets the
calls without those arguments through ungated. Literal tool names win over globs and the last match
wins, as for any approval. So a person reads every skill an agent publishes, in the approval preview
the harness renders: the SKILL.md that would be saved and, for an edit, the parent version and every
file kept from it by sha256.

```yaml
spec:
  skill_authoring:
    enabled: true
    mode: publish
  approvals:
    - id: skill-author
      description: Confirm saving a skill to the library
      tools: [create_skill, update_skill]
      ttl_seconds: 600
      allow_unattended: false
```

In either mode, an agent's edit of a version an operator wrote is saved as a draft and never
published automatically, and `submit_skill_feedback` only reaches library skills in this agent's own
catalog. Drafts and feedback are decided through [`/skill-library`](/guide/management-api/#skill-library).
The bundled `contributor` manifest enables authoring in `draft` mode; `governed` carries the
`skill-author` approval rule above.

## `spec.mcp_servers`

Each entry becomes one tool per remote tool, namespaced `{name}__{tool}`.

```yaml
spec:
  mcp_servers:
    - name: notion
      url: https://mcp.notion.example.com
      transport: sse
      auth: secret:NOTION_TOKEN
```

| Field | Type | Default | Notes |
|---|---|---|---|
| `name` | string | required | Tool namespace. |
| `url` | string | `""` | Required for `http` / `sse`. |
| `command` | string | `""` | Required for `stdio`. |
| `args` | string[] | `[]` | |
| `cwd` | string | `""` | |
| `env` | map[string,string] | `{}` | |
| `auth` | string | `""` | Literal token or `secret:NAME`. |
| `transport` | `http` \| `sse` \| `stdio` | `sse` | |
| `tools` | string[] | `[]` | Glob patterns over the **remote** tool names (`issue_write`, not `github__issue_write`). Empty binds every tool the server lists. Non-empty binds only matches, which is what lets an approval or policy rule enumerate a server's write tools rather than gate whatever it served on the day; a pattern that matches nothing is logged at bind time, not refused. |

Outbound URLs pass an SSRF guard. Parsing checks what needs no lookup — scheme, plain `http`
outside development, internal names and suffixes, and IP literals including the decimal form.
The address check happens when the connection is made: the harness resolves once, validates
every returned address, and connects to one it validated, so the address that was checked is
the address that is used. See [Egress](/internals/governance/#egress).

:::caution[stdio is disabled by default]
`transport: stdio` spawns a subprocess from manifest-supplied argv — arbitrary code execution as the
API process. It is refused unless the operator names the exact command in
`FELIX_MCP_STDIO_ALLOWED_COMMANDS` (comma-separated; empty, the default, disables stdio entirely).
The check runs on manifest **write** (`400`), at compile, and at spawn. The child inherits only
`PATH`, `HOME`, `LANG`, `LC_ALL`, `TZ` plus declared keys, and loader variables such as `LD_PRELOAD`,
`PYTHONPATH`, `NODE_OPTIONS` and `BASH_ENV` are rejected.
:::

## `spec.peers`

`name` and `url` are required; `auth` accepts a literal or `secret:NAME`. Hop depth is bounded by
`limits.max_peer_hops`.

## `spec.shell_tools`

Exec an allowlisted argv in the `FELIX_WORKSPACE_ROOT` checkout — the tool that lets a coding agent
run the repository's own gates. No shell interpreter: `&&`, `|` and `;` are literal arguments. It
runs as a child of the API process, or in a separate shell runner when `FELIX_SHELL_RUNNER_URL` is
set (below).

```yaml
spec:
  shell_tools:
    - name: run
      commands: [uv run ruff, ./scripts/test.sh, git status, git diff]
      timeout_ms: 300000
```

| Field | Type | Default | Notes |
|---|---|---|---|
| `name` | string | required | |
| `description` | string | `""` | Defaults to a sentence naming the allowed prefixes. |
| `commands` | string[] | required | argv prefixes, matched token for token from `argv[0]`. `git status` covers `git status --short`, not `git push` and not `git -c x status`. |
| `timeout_ms` | int \| null | `null` | Default 300 s; the process is killed at the limit. |
| `fatal` | bool | `false` | |

The tool takes `argv` (list), `cwd` (relative to the workspace root) and optional `stdin`, and
returns `exit_code`, `stdout`, `stderr` (each capped and marked `truncated`), `timed_out` and
`duration_ms`. `argv` is command-screened like a sandbox payload. The web UI's tool card
recognises that shape and leads with the exit status, drawing the two streams as streams rather
than as one JSON object.

:::caution[disabled by default]
Every prefix in `commands` must be covered by one in `FELIX_SHELL_ALLOWED_COMMANDS` (comma-separated;
empty, the default, refuses every shell tool). Checked on manifest **write** (`400`), at compile,
and per call. The child inherits only `PATH`, `HOME`, `LANG`, `LC_ALL`, `TZ`. What the allowlist
cannot bound: a listed command runs repository code. Without a shell runner that code runs as the
API's user, beside it, and can read the API process's environment through `/proc` — model keys,
database credentials, any token the API holds. Run untrusted work through a runner.
:::

**The shell runner.** `felix-shell-runner` executes shell tools in a container of its own. With
`FELIX_SHELL_RUNNER_URL` set, the API runs every check above, then sends the argv to the runner;
the runner checks the argv against its own `FELIX_SHELL_ALLOWED_COMMANDS` and the `cwd` against its
own `FELIX_WORKSPACE_ROOT` again, and kills the process group at the deadline or when the API goes
away. A runner that is down, errors, times out or answers anything malformed fails the call — it
never falls back to running the command in the API.

| Setting | Default | Notes |
|---|---|---|
| `FELIX_SHELL_RUNNER_URL` | `""` | Empty runs shell tools in the API process. Operator configuration only: no manifest or model can set it. |
| `FELIX_SHELL_RUNNER_TOKEN` | `""` | Bearer shared by the API and the runner; 32+ characters, required when the URL is set. |

The builder stack (`make up-self`) runs one: a `shell` service that shares only the workspace
volume, holds no secrets, sits on its own network so it cannot reach Postgres or Valkey, and runs
with `cap_drop: ALL`, `no-new-privileges` and a process limit. Workspace clone and fetch run there
too, since `git fetch` runs hooks the agent can write. It still has outbound internet for
`git fetch` and `uv`, so a builder host must not carry a cloud instance role.

## `spec.browser_tools`

Browser automation through the `browser` extra (Playwright). Install it explicitly — it is never in
the default image.

| Field | Type | Default |
|---|---|---|
| `name` | string | required |
| `description` | string | `""` |
| `binding` | string | required |
| `op` | `content` \| `links` \| `snapshot` \| `screenshot` \| `pdf` \| `json` | `content` |
| `timeout_ms` | int \| null | `null` | 1–3,600,000 ms. |
| `path_prefix` | string | `""` |
| `args_schema` | JSON Schema \| null | `null` |
| `fatal` | bool | `false` |

`screenshot` returns the viewport as an **image the model sees**, not base64 text. It rides on the
tool result and is stored in the attachment store under the request's tenant, with the same quota
and retention as an upload. A request keeps at most 16 tool images across every agent it runs, and 4 from any one call. The browser
is untrusted, so under `content_screening` each screenshot is screened by
`content_screening.image_model`. **Without `image_model` every screenshot is quarantined**, and the
build logs a warning saying so: set `image_model` to let screenshots through. A screenshot over 600
KiB is reported by size instead. `pdf` is not an image either wire can show and is still returned
inline as text, up to 32 KB.

## `spec.image_tools`

Image operations the model can run on the images in its conversation, backed by Pillow. Install the
`image` extra (`uv sync --extra image`, or `FELIX_DOCKER_EXTRAS=image`). Without it each tool still
binds and answers with what to install.

```yaml
spec:
  image_tools:
    - { name: list_images, op: list }
    - { name: thumbnail_image, op: thumbnail }
    - { name: crop_image, op: crop }
```

| Field | Type | Default |
|---|---|---|
| `name` | string | required |
| `description` | string | a description of the op |
| `op` | `list` \| `info` \| `resize` \| `crop` \| `rotate` \| `convert` \| `thumbnail` | required |
| `allow_path` | bool | `false` |
| `fatal` | bool | `false` |

One op per tool, so a manifest grants exactly the operations it names. A model sees an image's
pixels, not its file id, so every op except `list` takes `image`:
- `latest`, the default: the newest image in the thread's active branch;
- `#n`, as a `list` tool numbers them;
- a `felix-file://` reference the thread holds.

A reference to any other upload is refused. A tool whose entry sets `allow_path: true` also takes
`path`, a file under `FELIX_WORKSPACE_ROOT`. That directory is shared by every tenant on the host,
which is why reading it is opt-in. The ops' own arguments:

| Op | Arguments | Returns |
|---|---|---|
| `list` | none | The thread's images, newest last, as `#n` with where each came from |
| `info` | — | Format, size, mode and frame count, as text |
| `resize` | `width`, `height` (either alone keeps the aspect ratio) | The resized image |
| `crop` | `left`, `top`, `right`, `bottom` in pixels | The box |
| `rotate` | `degrees`, counter-clockwise | The rotated image, on a canvas grown to fit |
| `convert` | `format` (`png`, `jpeg`, `webp`, `gif`), `quality` | The re-encoded image |
| `thumbnail` | `max_size` for the longest side (default 512) | The shrunk image |

Each result comes back as an image the model sees. It is stored under the request's tenant, with
the attachment quota and retention, and it counts against the request's 16 tool images (charged
before anything is written). Its `felix-file://` reference is named in the reply, so the next call
can work on it.

Bounds:
- Only png, jpeg, gif and webp are parsed, as sniffed from the bytes, so no other Pillow decoder is
  reachable.
- Input is read up to 20 MiB, and an image whose header claims more than 4096×4096 pixels is
  refused before decoding.
- Output is at most 4096 px a side and is downscaled to fit the 600 KiB attachment limit.
- At most two images are decoded at once per process.

Under `content_screening`, results are screened according to where their input came from:
- with `image_model`, every result is screened like an untrusted tool's image;
- without it, a result made from a workspace file is quarantined, and one made from a thread image
  passes.

## `spec.search_tools`

Search the web through the backend an **operator** configured. The model supplies a query,
not a destination — the inverse of [`spec.http_tools`](#spechttp_tools) below, and the reason
this ref has no confinement field: the only address it reaches is
`FELIX_SEARCH_URL`.

```yaml
spec:
  search_tools:
    - name: search
      description: Search the web for sources.
      max_results: 8
  content_screening:
    enabled: true
```

| Field | Type | Default |
|---|---|---|
| `name` | string | required |
| `description` | string | `""` |
| `max_results` | int \| null | `null` (5); 1–20 |
| `fatal` | bool | `false` |

Configure the backend with `FELIX_SEARCH_BACKEND` (default `none`) and `FELIX_SEARCH_URL`.
**SearXNG** ships built in because it is self-hostable and needs no account; anything else —
Brave, Tavily, an internal index — is a plugin registering through
`felix.search.register_search_backend`, and the setting is validated against that registry at
startup. `FELIX_SEARCH_API_KEY` is optional and resolves through your secrets backend like any
other credential.

Results render as numbered `title / url / snippet` blocks, because the next thing an agent
does with a result is fetch its URL. A search **is** replay-safe, unlike a fetch: the endpoint
is yours and a query has no side effect.

<Aside type="caution" title="Turn on content screening with it">
A title and snippet are written by whoever ranked for the query, so results are untrusted
input — the transport is `search`, and [content screening](/internals/governance/) covers it
once enabled. Compiling a manifest that binds a search tool without
`spec.content_screening.enabled` logs `untrusted tool(s) … unscreened`.

Screening covers what comes **back**. It does not inspect the URL a model then hands to a
fetch tool, so pairing search with an unconfined `http_tools` entry is an egress path that
screening does not close — which is why the bundled `deep` manifest requires authentication.
</Aside>

<Aside type="note" title="Declaring one without a backend">
The tool still binds, and every call reports that `FELIX_SEARCH_BACKEND` is unset — rather
than the field silently doing nothing. The compile logs a warning too.
</Aside>

## `spec.http_tools`

Read a URL the **model** chooses. This is the inverse of an MCP server or an A2A peer, where
the manifest fixes the destination — so `path_prefix` is how an author narrows it back down,
and the caps live here rather than with the caller.

```yaml
spec:
  http_tools:
    - name: fetch_docs
      description: Read a page from the Felix documentation site.
      path_prefix: https://docs.felix.run/
      max_bytes: 60000
      timeout_ms: 10000
  content_screening:
    enabled: true
```

| Field | Type | Default |
|---|---|---|
| `name` | string | required |
| `description` | string | `""` |
| `path_prefix` | string | `""` — an absolute http(s) URL, normalised to end in `/` |
| `allow_any_host` | bool | `false` |
| `timeout_ms` | int \| null | `null` (15,000 ms); 1–3,600,000 ms |
| `max_bytes` | int \| null | `null` (100,000); up to 5,000,000 |
| `format` | `text` \| `raw` | `text` — renders HTML to readable text |
| `fatal` | bool | `false` |

An entry must set **either** `path_prefix` or `allow_any_host: true`; a manifest that sets
neither fails validation. Every other outbound ref names a destination you chose, so leaving
this one open by default would make unrestricted egress the path of least resistance.
`allow_any_host` is logged when the agent compiles.

The request is a `GET`. Redirects are followed up to five hops, and each hop is re-checked
against both the egress guard and `path_prefix` — a redirect cannot leave the prefix.
`timeout_ms` is a whole-call deadline covering the chain and every read, not a per-read
timeout. The body is streamed and truncated at `max_bytes`, counted after decompression. A
response that is not textual is described rather than decoded, and a non-2xx keeps its body,
because the error message is usually the useful part.

<Aside type="caution" title="Turn on content screening with it">
A fetched page is attacker-controlled input. The tool's transport is untrusted, so
[content screening](/internals/governance/) covers its output — but only once you enable it.
Compiling a manifest that binds a fetch tool without `spec.content_screening.enabled` logs
`untrusted tool(s) … unscreened`, and pages reach the model unexamined.
</Aside>

<Aside type="note" title="Not replay-safe">
A resumed run will not re-issue a fetch. The model names the endpoint, and a `GET` that
changes something is ordinary on the open web.
</Aside>

## `spec.github_publish`

Publish commits the agent already made in its workspace to GitHub, without the file contents
passing through the model. Binds one tool, `publish_commits`.

```yaml
spec:
  github_publish:
    repo: felix-run/felix
    auth: secret:GITHUB_MCP_TOKEN
    base: main
    branch_prefix: felix/
  approvals:
    - id: publish
      description: Publish these commits — read the diff in the preview
      tools: [publish_commits]
      one_shot: true
      bind_principal: true
```

| Field | Type | Default | Notes |
|---|---|---|---|
| `repo` | string | required | `owner/name` on github.com. |
| `auth` | string | required | A `secret:NAME` ref, never a literal — the value is a write credential. |
| `base` | string | `"main"` | The branch a new branch starts from, and one the tool never writes. Must not start with `branch_prefix`. |
| `branch_prefix` | string | required | Every branch the tool may create or move starts with this. |

The model calls `publish_commits(branch, head_sha, title?)`: a branch under `branch_prefix` and
the full sha of a commit it made locally. The harness reads those commits with read-only git and
writes them through GitHub's Git Data API — blobs, one tree, one commit, then the ref — so a
196 KiB file with a one-line change is never a tool argument.

- **An approval binds the content.** `head_sha` is an argument and commits are content-addressed,
  so approving one sha does not approve another on the same branch. Every blob sha GitHub
  returns, and the final tree, are checked against the local ones before the ref moves.
- **It only fast-forwards.** The new commit's parent is the branch's current remote tip (or
  `base`'s, for a new branch), which must be an ancestor of `head_sha`; the ref update is
  `force: false`. Several local commits publish as one commit listing their subjects.
- **The approval row shows the diff.** The harness computes the diff stat and unified diff
  between that parent and `head_sha` and attaches it as the row's `preview` (below); if it
  cannot, the call is refused rather than approved blind.
- **Bounds:** 300 files and 8 MiB per publish, the preview's diff capped at 32 KiB (the stat is
  never cut), 300 s per publish.
- **Where the token is.** Felix uses it in one HTTP client and passes it to no git process or
  workspace environment. Where shell tools run in the API process — `FELIX_SHELL_RUNNER_URL`
  unset — code the agent runs can still read that process's environment, token included; run
  them through a [shell runner](#specshell_tools), as the builder stack does. Either way keep the
  token's GitHub permissions to contents and pull requests, and its Workflows permission off.

## `spec.sub_agents` and `spec.aggregator_prompt`

`sub_agents` is a list of manifest names, required by the multi-agent patterns and resolved at build
time the way a request resolves a manifest — the tenant's stored versions, then object storage, then
bundled YAML. A name that resolves nowhere fails the compile; each child compiles once however many
parents name it, nesting deeper than four routers is refused, and so is a cycle. `aggregator_prompt`
(string, `""`) tells `parallel` and `groupchat` how to merge their results.

A child **inherits the caller's admission**: `spec.auth.inbound` is checked on the manifest a request
names, not again on each child. Put the admission you need on the router — a child's own
`required_scopes` apply when it is called by name, not when a router hands it a request. Everything
else a child declares (tools, policies, approvals, screening, limits) is compiled into it and applies
however it was reached. A `router` with [`spec.decider`](#specdecider) picks its child with the
decider and falls back to its model classifier when the decider is unsure.

## `spec.max_turns` and `spec.recursion_limit`

```yaml
spec:
  max_turns: 4          # rounds for the multi-agent patterns; default 4, ceiling 100
  recursion_limit: 10   # steps for a react loop; default 10, ceiling 50
```

They bound different loops. `max_turns` is read by `groupchat`, `plan_execute` and the other
delegating patterns. A `react` agent — the default pattern — is bounded by `recursion_limit`,
where one step is a model call plus the tool batch it asked for; `max_turns` on a react agent
bounds nothing, and the compile step warns (`felix_rule_targets_nothing{kind="max_turns"}`).
A react loop that runs out of steps with tool calls still pending ends with
`stop_reason: max_turns`, a `truncated` session status, and `felix_run_stop_reason{reason="max_turns"}`.

## `spec.memory`

```yaml
spec:
  memory:
    checkpointer: postgres   # default; `none` also built in
    store: pgvector          # default
```

<Aside type="caution">
  `checkpointer: none` keeps no session state, so anything that needs one has
  nothing to act on. A `session.strategy` other than `full_replay`,
  `session.compact_after_turn`, and `memory.capture.enabled` are each refused
  alongside it, rather than being silently dropped.
</Aside>

<Aside type="note">
  There is no in-process built-in on purpose. A thread is not manifest-scoped —
  the session routes address one by id with no manifest in hand — so a manifest
  choosing a different *backend* would leave the agent reading one log while
  `/history`, `/continue` and `/compact` read another. `none` is exempt because it
  is a claim about the agent, not a competing backend.
</Aside>

| Field | Type | Default | Notes |
|---|---|---|---|
| `checkpointer` | `postgres` \| `none`, or a registered name | `postgres` | Where the session log lives. `none` keeps no session state, so every turn starts from the messages it was given. Add your own with `register_checkpointer`. |
| `store` | `pgvector` \| `memory` \| `none` (aliases `agentcore`, `vectorize` accepted but inert) | `pgvector` | Durable-fact vector store. |
| `capture` | object | disabled | Extract durable facts from a turn. |
| `recall` | object | tools off | How stored facts reach the model beyond the prelude. |
| `consolidate` | object | disabled | Periodically merge agent-written facts that say the same thing (below). |

The bundled `assistant` manifest is the worked example: `capture` on `claude-haiku` with
`max_facts: 3` and `min_chars: 200`, `recall.tools: true`, `content_screening` on, an approval
(`memory-forget`) on `forget`, and `auth.inbound.allow_anonymous: false`. Memory is keyed by tenant
and manifest, not by caller, so a manifest that captures on a deployment shared by more than one
person puts one caller's facts in another's prompt.

### `memory.consolidate`

Capture only adds, so a pool of facts grows on every long turn. Consolidation merges the ones that
say the same thing.

```yaml
spec:
  memory:
    consolidate:
      enabled: true
      model: claude-haiku
      after_facts: 50
      max_facts: 200
```

| Field | Type | Default | Notes |
|---|---|---|---|
| `enabled` | bool | `false` | Opt in, per manifest. |
| `model` | string | `"claude-haiku"` | The route asked which facts are duplicates. Its calls are metered to the tenant and manifest. |
| `after_facts` | int ≥ 10 | `50` | Only a pool holding more than this many eligible facts is considered. |
| `max_facts` | int 1–500 | `200` | The newest facts shown per pass. |

The worker's `consolidate_memory` cron (every 15 minutes) shows the model the newest `max_facts`
active facts of the pool and asks which state the same thing. What it is allowed to do is narrow
on purpose:

- **It only merges duplicates.** Facts that merely relate, or that disagree, are left as they are.
- **The model returns groups of ids, never text.** The store keeps the **oldest** fact of each group
  — the model's ordering is ignored — and supersedes the rest, which stay stored and auditable.
  No memory text is ever written by consolidation.
- **Only agent-written facts.** Facts an operator wrote through `/memory` are never shown and never
  retired. Facts of a different `kind`, or a different `topic_key` (absent counts), are never merged.
- **Every group is checked first** — ids from the batch shown, none in two groups — and is applied
  whole or not at all; a malformed answer changes nothing.
- **A pool that has not changed is not asked again**, and at most 50 pools are consolidated per
  tick. The skip is remembered per worker process, so a restart costs one call per pool.

Facts reach the model fenced as untrusted data, since capture extracts them from turns that can
include tool output.

`capture`:

| Field | Type | Default |
|---|---|---|
| `enabled` | bool | `false` |
| `model` | string | `"claude-haiku"` |
| `max_facts` | int, 1–20 | `5` |
| `min_chars` | int ≥ 0 | `80` |
| `verify` | bool | `false` |

`verify` adds a second pass that hands the proposed facts back to `model` along with the excerpt and
keeps only what the excerpt actually supports. It doubles the extraction calls, which is why it is
off by default — turn it on where stored memory is acted on rather than merely recalled.

The pass can only **remove**. Its verdict selects from the proposals; it never supplies a memory of
its own, and it cannot alter a kept memory's `kind`, `topic_key` or `importance`. That matters
because the excerpt it reads is untrusted transcript. A captured `topic_key` cannot retire anything
— only an operator retires a memory by its key, and a captured value is stored beside the one it
contradicts — but a verdict that could set a key could still make its own memory the one the
prelude shows as current.

It fails open on anything it cannot read, on the grounds that a broken verifier is not evidence the
facts were wrong:

| Verdict | Result |
|---|---|
| A subset of the proposals | Just that subset is stored |
| `[]` — a well-formed empty array | Nothing is stored. The one unambiguous way to reject everything |
| The call errors | The unverified set is kept |
| Unparseable, or every item unusable | The unverified set is kept |
| Valid items that match no proposal | The unverified set is kept — the verifier rewrote rather than chose |

Content is matched case- and whitespace-insensitively but not punctuation-insensitively, so a
verifier that echoes an item back with a trailing full stop counts as having rewritten it.

Extraction runs on `model`, not on the turn's model — it is a small, mechanical job on every
completed turn, and billing it to a frontier model roughly doubles the cost of having memory at
all. If that model cannot be built, extraction falls back to the turn's model rather than dropping
the fact.

Facts land in `memory_vectors` (pgvector, HNSW) with one of four kinds: `fact`, `event`,
`instruction`, `task`. The extractor asks the model to classify each fact, and **anything outside
that set is silently rewritten to `fact`** rather than rejected — so a prompt that invents a kind
degrades quietly instead of failing.

Stored facts reach the model two ways. The **prelude** — the active facts, which the ReAct loop
renders as a message directly after the system prompt on each run — is built whenever `store` is
`pgvector` or `memory`; it is escaped but bypasses the governance stack. `recall`:

| Field | Type | Default | Notes |
|---|---|---|---|
| `tools` | bool | `false` | Bind `remember`, `recall`, `forget` and `list_memories`. They are bound before the governance stack, so recalled text passes through content screening, policies and approvals like any tool output. Not bound when `store: none`. |
| `limit` | int, 1–50 | `5` | Default number of hits `recall` returns. |

Recall is hybrid: full text, topic keys, and a vector channel when `FELIX_MEMORY_EMBEDDER` resolves
to an embedder. The default, `auto`, uses the local model when `felix-harness[embeddings]` is
installed and skips the vector channel otherwise — see [Embeddings](/guide/deploy/#embeddings).

Procedural memory is a separate subsystem under `spec.procedural_memory`, not a kind in this table.

## `spec.execution`

```yaml
spec:
  execution:
    mode: durable        # default: transient
    tools: sequential    # default
    webhooks: [ops]      # durable only; ids from FELIX_WEBHOOK_ENDPOINTS
```

| Field | Type | Default | Notes |
|---|---|---|---|
| `mode` | `transient` \| `durable` | `transient` | `durable` runs the invocation as a **fiber**. |
| `resume_token_ttl_seconds` | int \| null | `null` → `FELIX_HIBERNATE_AFTER_SECONDS` (300) | |
| `tools` | `parallel` \| `sequential` | `sequential` | Tool-call execution within a batch. |
| `webhooks` | string[] (≤ 8) | `[]` | Endpoint **ids** announced to when the run ends. Needs `mode: durable`. Each must match `^[a-z0-9][a-z0-9_-]{0,63}$` and be registered in `FELIX_WEBHOOK_ENDPOINTS` for the caller's tenant, or the run is refused with `422 unknown webhook endpoint: <id>`. |

A durable `POST /chat` returns **`202`** with `{status, resume_token, fiber_id, expires_at,
thread_id}`; poll `GET /chat/runs/{resume_token}`. Fibers checkpoint in Postgres and are picked up
by the worker within about a second (`FELIX_FIBER_POLL_SECONDS`, see
[Deploy → Durable runs](/guide/deploy/#durable-runs)). Fibers are the one durable backend; the
Temporal backend was removed, and `FELIX_DURABILITY=temporal` now fails startup.

`POST /chat/stream` on a durable manifest streams the run instead — `run_accepted`, `run_status`,
`final` — and a client that disconnects reattaches with the resume token (see
[REST API](/guide/rest-api/#post-chatstream)).

`webhooks` names endpoints, never URLs: the operator registers each one's URL, signing secret and
allowed tenants, and the worker POSTs the finished run to it. See
[Completion webhooks](/guide/rest-api/#completion-webhooks) for the payload and signature, and
[Deploy](/guide/deploy/#completion-webhooks) for registering endpoints.

## `spec.decider`

A **decision model** answers typed questions — pick one option, score against levels, true or false —
with calibrated probabilities instead of generating text. Naming one here does nothing on its own;
each consumer opts in with its own flag, and each keeps its previous behaviour as the fallback.

```yaml
spec:
  decider:
    id: jev              # a FELIX_DECISION_ROUTES id
    min_confidence: 0.5
```

| Field | Type | Default | Notes |
|---|---|---|---|
| `id` | string | `""` | Off when empty. `jev` (TypeSafe) and `jev-cf` (Jev on Workers AI) are built in; an id not in `FELIX_DECISION_ROUTES` fails the compile. |
| `min_confidence` | float 0–1 | `0.5` | Below this a consumer treats the decision as unsure and takes its fallback. |

| Consumer | Flag | What the decider decides |
|---|---|---|
| Tool selection | `tools_retrieval.decider` | Which tools the model is offered this turn |
| Router | `pattern: router` with `decider.id` set | Which sub-agent answers |
| Escalation | `model.confidence_escalation.decider` | Whether the reply answers the request |
| Judges | `guardrails.judges[].decider` | Probability the text meets `criteria` |
| Reflect | `reflect.decider` | Whether a draft meets the criteria |
| Skill hints | `skill_suggestion.enabled` | Which skill fits a task, sent as a hint |
| Screening | `content_screening.decider` | Injection, jailbreak and exfiltration risk |

Every decision is metered like a model turn and counts against `limits.max_cost_usd`. The request
text — and, for the consumers that judge them, replies and tool output — goes to the decider's
provider unmasked. The bundled `decider-support` manifest switches on every consumer that fits a
support agent. See [Model client](/internals/model-client/#decision-models).

## `spec.skill_suggestion`

Ranks the skill catalogue with [`spec.decider`](#specdecider), reranks a shortlist against each
skill's body, and — only when the request asks for a task and a skill fits it — adds a one-line hint
naming that skill. The model still decides whether to `activate_skill`. The hint rides the turn's
first model call as a transient message: after the prompt-cache breakpoint, never in the session log.

| Field | Type | Default | Notes |
|---|---|---|---|
| `enabled` | bool | `false` | Needs `spec.decider.id`; `react` and `deep` only. |
| `shortlist` | int 1–10 | `3` | Skills carried into the rerank; a catalogue no larger skips the ranking. |
| `min_gate` | float 0–1 | `0.3` | Probability the request asks for a task at all. |
| `min_fit` | float 0–1 | `0.3` | Probability the best skill does what was asked. |

## `spec.artifacts`

Spills oversized tool output to the object store, shows the model a preview, and gives it a tool to
read the rest.

| Field | Type | Default | Meaning |
|---|---|---|---|
| `enabled` | bool | `false` | Spill, and bind `read_artifact` |
| `threshold_chars` | int ≥ 1 | `8000` | A tool result longer than this is spilled |
| `preview_chars` | int ≥ 1 | `200` | How much of it stays in the transcript |
| `default_window_chars` | int ≥ 1 | `4000` | `read_artifact` window when the model gives no `length` |
| `max_window_chars` | int ≥ 1 | `16000` | Largest window one `read_artifact` call returns |

Output over the threshold is written to `artifacts/{tenant}/{manifest}/{uuid}.txt` and replaced with
the preview plus a marker, which is always the last thing in the output:

```
…[artifact:<id> key=artifacts/<tenant>/<manifest>/<id>.txt chars=<N> spilled_at=<unix>]
```

**The model reads it back with `read_artifact`**, bound automatically whenever `enabled` is true and
an object store is configured:

| Argument | Type | Default |
|---|---|---|
| `artifact_id` | string | — the id from the marker |
| `offset` | int ≥ 0 | `0` |
| `length` | int ≥ 1 | `default_window_chars`, capped at `max_window_chars` |

Each window comes back headed `[artifact-window:<id> chars <start>-<end> of <total>; continue at
offset=<end>]`, or `; end]` on the last one, so the model pages by the offset it was given.

- **It reads only what its own conversation spilled** — the thread, or the request when there is no
  thread. The tenant and manifest prefix is shared by every caller of a manifest, so an id alone
  would otherwise reach another caller's run. Another conversation's id is refused exactly as a
  missing one is.
- **It is governed like any tool.** It is bound before the governance stack, so policies, limits,
  screening and audit apply to a read as to the call that produced the artifact.
- **It is never itself spilled**, although a window can be larger than `threshold_chars`.
- **Spill expires.** The worker's retention sweep deletes spills older than
  `FELIX_ARTIFACT_RETENTION_DAYS` (30 by default, `0` keeps forever); after that `read_artifact`
  reports the id as missing.

Clients read artifacts through [`GET /artifacts`](/guide/management-api/#artifacts) instead, which
needs `artifacts:read` and is not held to a conversation. The bundled manifests that read files or
fetch pages — `contributor`, `cowork`, `triage`, `deep`, `support` — enable artifacts.

## `spec.plan_execute`

| Field | Type | Default |
|---|---|---|
| `planner_model` | string | `""` |
| `executor_model` | string | `""` |
| `max_subtasks` | int 1–20 | `8` |
| `replan_on_failure` | bool | `true` |
| `max_replans` | int 0–5 | `2` |
| `executor_recursion_limit` | int 1–20 | `6` |

`planner_model` routes the planning turn and `executor_model` the per-subtask agent; empty
keeps `spec.model` for that turn, and everything else on `spec.model` — price overrides,
fallbacks, thinking level — is carried across either way. Naming a planner route chooses
which route plans, not which model configuration applies. A `model` named on the request
outranks both.

`replan_on_failure` replaces the *unfinished remainder* of the plan when a subtask ends
early, keeping the completed steps and their notes; `max_replans` bounds it, and `0` turns
it off as surely as the boolean does. "Ends early" means the subtask stopped on `refusal`
or `max_tokens` — a governance denial or a truncated answer. A short answer is not a
failure, so it does not replan. `max_subtasks` bounds the whole run, not each plan: a
replan is asked only for the budget the ceiling has left.

:::caution[Removed after 0.3.0]
`planner_few_shots` is gone. It named a count of planner examples with no corpus behind it,
so nothing could make it mean anything. A stored manifest that sets it still loads — the
field is stripped on read with a warning rather than failing under `extra: forbid`. Delete
the line to clear the warning; nothing else changes, because nothing ever read the value.
:::

## `spec.policies`

Scope-gated tool access.

```yaml
spec:
  policies:
    - id: notion-writes
      required_scopes: [notion:write]
      tools: ["notion__create_page"]
```

| Field | Type | Default |
|---|---|---|
| `id` | string | required |
| `description` | string | `""` |
| `required_scopes` | string[] | required, non-empty |
| `tools` | string[] (glob, e.g. `github__*`) | required, non-empty |

Both lists are required. A rule with `tools` and no `required_scopes` permits every caller
while appearing to govern them, and one with no `tools` gates nothing while still counting
toward the `soc2` profile — so both are rejected at parse rather than accepted as no-ops.

Globs match in any position and are case-sensitive. A pattern matching no bound tool is logged
and counted as `felix_rule_targets_nothing` at compile time rather than refused, since an MCP
server whose discovery failed binds no tools.

A denial emits a `policy_deny` audit event with `status: denied`.

## `spec.limits`

```yaml
spec:
  limits:
    max_tool_calls: 200
    max_wall_clock_seconds: 3600
```

| Field | Type | Default | Absolute ceiling |
|---|---|---|---|
| `max_tool_calls` | int \| null | `null` | **500** |
| `max_wall_clock_seconds` | float \| null | `null` | **3600** |
| `max_peer_hops` | int \| null | `null` | **5** |
| `max_input_tokens` | int \| null | `null` | **1,000,000** |
| `max_output_tokens` | int \| null | `null` | **100,000** |
| `max_cost_usd` | float \| null | `null` | **1,000.00** |
| `precount` | bool | `false` | Count input tokens before the call rather than after. |

`max_cost_usd` is a per-run spend ceiling, accumulated from the model catalog's prices as tokens are
metered. It fails closed: a model the catalog cannot price is a pricing gap that mis-enforces the
cap, so supply `spec.model.price` for any model you route to that the built-in table does not
cover.

`spec.recursion_limit` (int \| null, ceiling **50**) and `spec.max_turns` (ceiling **100**) are
capped the same way. A breach denies the call like any other governance layer: the tool result
becomes a deny string, `felix_tool_calls{status="denied"}` increments, and the run records a
`policy_deny` audit row. There is no distinct `limit_exceeded` event type.

## `spec.guardrails`

```yaml
spec:
  guardrails:
    providers: [pii]
    block_on_match: true
    targets: [input, output, final_response]
    judges:
      - name: helpfulness
        criteria: "Answers the question without inventing facts."
        threshold: 0.7
```

| Field | Type | Default |
|---|---|---|
| `providers` | list of `pii` | `[]` |
| `block_on_match` | bool | `false` |
| `targets` | list of `input` \| `output` \| `final_response` | `["input","output"]` |
| `judges` | JudgeRule[] | `[]` |

`JudgeRule`: `name` (required), `criteria` (required), `threshold` (float 0–1, default `0.7`),
`model` (string, `""`), `target_tools` (string[], `[]`), `final_response` (bool, `false`),
`decider` (bool, `false`).

A judge scores with, in order: [`spec.decider`](#specdecider) when `decider: true` — the probability
the text meets `criteria`, read as written, so a negative criterion needs no `assert_absent:` prefix —
then the model in `model`, then the heuristic. Each failure falls through to the next. Text longer
than 8,000 characters skips the decider, which would otherwise judge only a prefix. A decider judge
is a quality control, not a security boundary: the text it judges can argue for its own verdict.

`providers` is a closed set, like `targets` beside it: a typo (`PII`, `pii-redaction`) is a
compile error rather than a manifest that applies no wrapper while reporting guardrails enabled.

The `pii` provider needs the `pii` extra (Presidio) **plus a spaCy English model**. Without both —
which is the case on the lean image — it degrades to three regexes (email, US SSN, card-like digit
runs), announced at `WARNING` with a `felix_control_degraded` counter, not silently. Guardrail
blocks and below-threshold judge scores deny through the same path as every other layer — a
`policy_deny` audit row and `felix_tool_calls{status="denied"}` — not under event types of their
own.

## `spec.content_screening`

Screens tool **output** for prompt injection before the model sees it.

| Field | Type | Default | Notes |
|---|---|---|---|
| `enabled` | bool | `false` | |
| `model` | string | `""` | Empty = marker-based only; set an id to add an LLM injection score. |
| `tools` | string[] | `[]` | Screened **in addition to** every untrusted tool — anything not executing in-process: MCP, peers, browser, sandbox, container, queue, fetch, any plugin transport — which is always screened. |
| `on_flag` | `quarantine` \| `block` | `quarantine` | Applies to output that is flagged **and** to output that could not be screened. |
| `decider` | bool | `false` | Also ask [`spec.decider`](#specdecider): injection, jailbreak and exfiltration in one call. |
| `model_tools` | string[] (globs) | `[]` | Which screened tools get the **paid** scoring — `model` and `decider`. Empty = every screened tool. Needs `model` or `decider: true`. |
| `image_model` | string | `""` | A vision model that reads the text in each **user image**, and in each image a screened tool returns; the transcript is screened like typed text. `on_flag` applies per user image; a tool's image is always quarantined, never refused. Empty = user images are not screened, and an untrusted tool's images are quarantined. Needs `enabled: true`. |

`decider` is **additive**: the markers run first, `model` runs beside it, either one flagging flags,
and either one unable to run leaves the text unscreened rather than cleared. A decider is not
adversarially robust, so it is an extra net, never a replacement for the model screener. The model
screener and the decider read tool output and user turns window by window across the whole text;
output longer than eight windows (32,000 characters) is reported unavailable, so `on_flag` decides.

`model_tools` is a cost lever, not an exemption. The model screener and the decider cost a call
per window, so a manifest binding twenty MCP tools pays twenty a turn; `model_tools` names the
ones worth paying for. The marker scan still runs on **every** screened tool, so an untrusted tool
left out of `model_tools` is screened by markers alone — never unscreened. A pattern matching no
bound tool is counted as `felix_rule_targets_nothing`.

```yaml
content_screening:
  enabled: true
  decider: true
  model_tools: ["github__get_*", "browser__*"]
```

Inbound user turns are screened on `/chat`, `/v1` and `/a2a` as well.

### Images

A turn's screeners read its text. Text drawn *inside* an image — a screenshot that says "ignore
previous instructions" — is invisible to them unless `image_model` is set:

```yaml
content_screening:
  enabled: true
  image_model: claude-sonnet   # any vision-capable model id
  on_flag: quarantine
```

Each user image is sent to that model to be transcribed, and the transcript goes through the same
marker scan, `model` score and decider as the turn's own text. Under `quarantine` a flagged image
is removed and the turn carries `[quarantined] image flagged as potentially hostile` in its place;
the text and any clean images still reach the agent. Under `block` the turn is a `422`.

- An uploaded image (`POST /files`, then a `file` content part) is read under your tenant before it
  is transcribed, so the screener sees exactly the bytes the model will.
- A remote `https://` image is **not** screened: the model provider downloads it separately, so
  there is no way to know the screener and the model got the same picture. It is treated as a
  screener outage — removed under `quarantine`, `503` under `block`. Send image bytes or upload
  them when screening is on.
- Each distinct image costs one vision call, with at most 8 per request across all its messages;
  past that, `block` answers `422 too_many_images` and `quarantine` removes the rest. Transcripts
  are cached per tenant by content, so a client that resends its conversation every request pays
  once per image.
- A transcript counts only if the transcriber finished normally. A refusal, a filtered or
  truncated reply, or an empty one is treated as unscreened; `NO_TEXT` is the only answer that
  means "no text".
- **History is screened as well as the incoming turn.** An image already in the thread —
  sent through a different manifest in the same thread, or before `image_model` was set — is
  screened whenever the history is rebuilt for the model, including after compaction. A flagged
  replayed image is always quarantined, even under `block`: refusing would refuse every later
  turn of the thread, since its history can't be rewritten. A router's image screen also applies
  to the sub-agents it hands the thread to, on top of any screen of their own.
- It screens for injection only: the input PII guardrail does not read image text.
- The transcriber reads the image it is screening, and a crafted image can try to talk it out of
  reporting its text. Treat this as one layer, like every model-based screener.

A screener that cannot run has not cleared anything. If the model is unreachable — missing key,
expired credential, 429, provider outage — or returns a score that cannot be parsed, the result is
*unavailable*, not clean: `on_flag: block` denies (inbound: `503`), `quarantine` replaces the
content, and a `felix_control_unavailable` counter is emitted. This matters most on the tool-output
path, which is what screens MCP, A2A, browser, and sandbox content.

## `spec.approvals`

Human-in-the-loop gates on named tools.

```yaml
spec:
  approvals:
    - id: workspace-write
      description: Confirm writes to the workspace
      tools: [write_file]
      ttl_seconds: 600
      one_shot: true
      bind_principal: true
```

| Field | Type | Default | Notes |
|---|---|---|---|
| `id` | string | required | |
| `description` | string | `""` | Shown to the approver. |
| `tools` | string[] | `[]` | |
| `ttl_seconds` | int > 0 \| null | `null` | How long the run waits for a decision. |
| `one_shot` | bool | `false` | The grant is consumed once — by the call that waited for the decision, or by the first identical call that finds it. Enforced with a conditional update, so two concurrent identical calls cannot both spend it: a waiting call that loses is refused with `[approval already used]`, and one that finds the grant already spent asks for a new approval. |
| `bind_principal` | bool | `false` | The grant is bound to the principal that asked; it will not authorize another user's identical call — including while it waits: an identical call from another principal is refused rather than joining the pending request. |
| `allow_unattended` | bool | `false` | Permit the call with no human present. |
| `when_args` | string[] | `[]` | Gate only the calls carrying **all** of these arguments, non-empty. Empty gates every call. |

`when_args` exists because a tool can be harmless in one shape and a privileged
operation in another. `remember` is ordinary capture until it carries a `topic_key`, at
which point its value becomes the one the model is shown as current for that topic. It no
longer retires what else holds the key — only an operator does that — but a human seeing a
key-changing write is still worth an approval. Gating the whole tool would put one in front
of every memory write:

```yaml
spec:
  approvals:
    - id: memory-retopic
      description: Confirm a new current value for a remembered topic
      tools: [remember]
      when_args: [topic_key]
```

A call that does not carry every named argument reaches the tool untouched — no
approval, no `approval_required` event, no added latency.

A gated call creates a pending row keyed by a SHA-256 signature of its arguments, emits
`approval_required`, and blocks on the decision. Operators answer with
`POST /approvals/{id}/decide` (`approved` / `denied`, optional `note`, optional `edited_args` which
replace the call arguments). It **fails closed**: no request context, no store, or a store error all
deny.

A tool can attach a **preview** the harness computes from the call — `publish_commits` attaches
the diff it is about to publish. It appears on the pending row and the `approval_required` frame
as `args.preview`, is never part of the signature, and is stripped from `edited_args`. A preview
that fails refuses the call (`[approval preview failed]`) and writes no row, so nothing is
approved unseen.

## `spec.governance`

Opt-in framework mapping. These are compile-time requirements, **not a certification**.

```yaml
spec:
  governance:
    frameworks: [soc2]
    forbid_plaintext_secrets: true
    pin_compile: true
    retention_days: 365
```

| Field | Type | Default | Notes |
|---|---|---|---|
| `frameworks` | list of `soc2` \| `eu_ai_act` | `[]` | Empty is a no-op, so local manifests stay valid. |
| `risk_tier` | `limited` \| `high` | `limited` | EU AI Act deployer hint. |
| `transparency_notice` | bool | `false` | Prepends an "you are talking to an AI agent" notice. |
| `forbid_plaintext_secrets` | bool | `false` | Also forced on when `FELIX_ENVIRONMENT=production`. |
| `pin_compile` | bool | `false` | Freezes the manifest version for a thread — and every sub-agent it compiles, recursively; drift → `409`. |
| `retention_days` | int 1–3650 \| null | `null` | Shortens this manifest's **audit** rows below `FELIX_AUDIT_RETENTION_DAYS`, never lengthens them. Does not reach its spilled artifacts, which follow `FELIX_ARTIFACT_RETENTION_DAYS`. |

Setting any framework forces `forbid_plaintext_secrets` and `pin_compile` to `true`, and then:

**`soc2`** requires `observability.trace: true`, `anomaly.enabled: true`, at least one of
`policies` / `approvals` / `limits`, at least one of `auth.inbound.schemes` / `required_scopes`, and
`auth.inbound.allow_anonymous: false` outside development.

**`eu_ai_act`** requires `governance.transparency_notice: true` and at least one of
`content_screening.enabled` or guardrails targeting `input`. With `risk_tier: high` it additionally
requires a non-empty `approvals` list in which no rule sets `allow_unattended: true`.

Verify in CI with `felix validate-manifest <file> -e production`. See
[`deploy/GOVERNANCE.md`](https://github.com/felix-run/felix/blob/main/deploy/GOVERNANCE.md).

## Secret references

Anywhere a credential is accepted (`mcp_servers[].auth`, `peers[].auth`, `containers[].auth`) you may
write a literal, `secret:NAME`, or `{"secret": "NAME"}`. Names resolve at compile through
`FELIX_SECRETS_BACKEND` (`env` | `file` | `aws` | `gcp`) and are masked out of tool output. An
unresolvable name fails the request with **`503`**. With `forbid_plaintext_secrets` on, a literal is
a compile error.

## Fields that parse but do nothing yet

Do not build on these — they validate, but no code path consumes them:
`spec.anomaly.min_rate`.

`memory.checkpointer` used to be on this list. It now selects the session store for
real, and the three names that could never work here — `agentcore`, `do` (Durable
Objects, which this stack does not run) and `sqlite` — are a validation error rather
than a silent alias for `postgres`.
