import { Aside, Steps } from '@astrojs/starlight/components';

Skills published on GitHub enter the [skill library](/guide/management-api/#skill-library) the same
way an agent's do: as a **draft** that no catalog loads until a person publishes it. Felix fetches
the skill itself, pinned to one commit of the repository's own history, from `api.github.com` only,
through the [egress guard](/internals/governance/#egress). Nothing resolves a GitHub ref at manifest
compile time — `spec.skills` and the catalog loader never call GitHub — so a compile never depends
on GitHub being up.

| Method | Path | Scope | Success | CLI |
|---|---|---|---|---|
| `GET` | `/skill-library/-/browse?source=&ref=` | `skills:read` | `200` | `felix skills browse` |
| `POST` | `/skill-library/-/import` | `skills:write` | `201`, or `200` unchanged | `felix skills add` |

Publishing is the library's ordinary
`POST /skill-library/{name}/versions/{version}/publish`, after review. Checking an imported skill against its origin,
diffing it and re-importing it are in [Update checks](#update-checks).

<Aside type="caution">
With `FELIX_AUTH_MODE=none` the scope checks are skipped entirely, so anyone who can reach the API
can browse and import through the server's GitHub token, and publish what they imported.
</Aside>

## Quickstart

For a deployment whose tenant `acme` keeps its skills in the GitHub repository `acme/skills`:

<Steps>

1. **Configure the API** and restart it. The token is optional for a public repository; with one
   set, every allowlist entry must name a tenant and a literal owner, or boot refuses.

   ```bash
   FELIX_SKILL_IMPORT_GITHUB_TOKEN=...      # read-only Contents access to acme/skills
   FELIX_SKILL_IMPORT_SOURCES=acme=github:acme/skills
   ```

2. **Browse** the repository. Each line is the `source` to import by, the skill's name, and its
   description.

   ```bash
   felix skills browse github:acme/skills --url https://felix.example.com
   ```

3. **Import** one as a draft. A new skill starts at `0.1.0`.

   ```bash
   felix skills add github:acme/skills/skills/pdf-forms --url https://felix.example.com
   ```

4. **Review** the draft: its files (`GET /skill-library/pdf-forms/versions/0.1.0`) and what the gate
   would say (`GET /skill-library/pdf-forms/versions/0.1.0/preview`), or the chat-ui Skills page's
   review queue.

5. **Publish** it. The publish gate holds an import to a [stricter bar](#review-and-publish).

   ```bash
   curl -s -X POST "$BASE_URL/skill-library/pdf-forms/versions/0.1.0/publish" \
     -H "authorization: Bearer $FELIX_KEY" | jq
   ```

</Steps>

The CLI authenticates with `--api-key` or `FELIX_API_KEY` (a key with `skills:read` to browse,
`skills:write` to add), else the token `felix login --save` kept for that server. `--url` defaults
to `http://localhost:8080`.

## Sources and refs

A **source** is `github:owner/repo[/path]`; the path is the directory holding the skill's
`SKILL.md`, and a skill at the repository's root has none. Owner and repository are lowercased,
since GitHub treats them case-insensitively, and a trailing `.git` is dropped. The owner is a
GitHub owner name; the repository is `A-Z a-z 0-9 . _ -`; the path is at most 16 segments of
`A-Z a-z 0-9 . _ -`, none of them `.` or `..`. Anything else is `422 invalid_source`. The source
is at most 512 characters.

A **ref** is separate — `ref` in the query or body, `--ref` on the CLI — at most 200 characters,
and resolved to one commit before anything else is read. Every later call names that commit, so a
branch that moves mid-import cannot mix two commits into one version.

| Ref | Resolves as |
|---|---|
| omitted | The repository's default branch, looked up as `refs/heads/<default>` — so a default branch named like a commit id is still a branch |
| hex, 7–64 characters, any case | A commit id and nothing else, never a branch or tag. GitHub must return a commit that starts with the hex given, or it is `422 ambiguous_ref` (a branch or tag of that name answered instead). The commit must then be **on the default branch** — its tip or an ancestor — or it is `422 commit_not_in_repo` |
| `refs/heads/<name>`, `refs/tags/<name>` | That branch or tag, through the repository's own refs |
| the default branch's name | That branch, as `refs/heads/<default>`, even when a tag shares the name. An import with no ref stores the default branch's name as its ref, so a later `main` tag cannot turn that stored ref ambiguous or into the tag |
| any other name | Looked up as a tag and as a branch. One that is both is `422 ambiguous_ref`: spell it `refs/tags/<name>` or `refs/heads/<name>`, so a branch cannot shadow a release tag. One that is neither is `404 source_not_found` |

The reachability check exists because GitHub serves any commit in a repository's fork network under
the upstream's name: a commit pushed only to a fork would otherwise read as the upstream's, past an
allowlist that trusts the upstream. A comparison GitHub cannot answer, or one too large to read,
fails closed. An annotated tag is followed to its commit, at most four tags deep. Every file is
read by blob id and checked against its git object id, and every commit is reported in full.

## Browse

`GET /skill-library/-/browse?source=github:acme/skills` lists the skills a repository offers at one
commit: every directory holding a `SKILL.md` under one of these roots, anywhere in the tree.

| Roots |
|---|
| `skills`, `.claude/skills`, `.claude/plugins/marketplaces`, `.agents/skills`, `.cursor/skills`, `.gemini/skills`, `.codex/skills`, `.vscode/skills` |

A root counts as a path segment at any depth, so flat layouts (`skills/<slug>/SKILL.md`) and plugin
and marketplace layouts (`plugins/<plugin>/skills/<slug>/SKILL.md`) are both found. With a path in
the source, only skills under it are listed, and the path itself counts as a root, so a layout no
default root covers can still be listed. A directory whose name is not a valid skill name, or whose
path is not a valid source, is skipped; of two directories with one name, the first in tree order
wins.

The answer is `{source, ref, commit, license, min_age_days, items, found, truncated}`: `ref` is the
ref asked for or the default branch, `commit` the full SHA every `SKILL.md` was read at, and
`license` the repository's SPDX id, or `null`. Each item is:

| Field | |
|---|---|
| `name`, `description` | From the `SKILL.md` frontmatter, read from its first 64 KiB only; `name` falls back to the directory name |
| `path` | The directory in the repository |
| `source` | What to import it by: `github:owner/repo/path` |
| `first_seen_at`, `eligible_at` | When this tenant first saw these exact files (this browse, if never before), and when the [cooldown](#the-cooldown) lets them in, in epoch ms |
| `eligible` | Whether an import now would pass the cooldown; always `true` with none |

A browse lists at most 50 skills; `found` is how many there were and `truncated` says some were
left out — name a path to narrow it. **A browse starts the cooldown clock** of every skill it lists.

## Import

```bash
curl -s -X POST "$BASE_URL/skill-library/-/import" \
  -H "authorization: Bearer $FELIX_KEY" -H 'content-type: application/json' \
  -d '{"source":"github:acme/skills/skills/pdf-forms","ref":"v1.2.0"}' | jq
```

`POST /skill-library/-/import` takes `{source, ref, publish}` and saves the skill as a draft with
`source: import`. `publish: true` is refused `422 publish_not_allowed`: an import is read first,
then published by a separate request. The answer is the saved version's record — with `files`,
`published: false` and `publish_blocked: null` — plus `unchanged` and `dropped_files`.

- **The name is the folder's.** The skill is saved under the source's last path segment (the
  repository's name for a skill at its root), and a `SKILL.md` naming anything else is
  `422 invalid_bundle`.
- **A new skill starts at `0.1.0`.** A skill the library already imported from the same source gets
  a new version, built on its newest version that was not rejected.
- **Unchanged files save nothing.** Change is judged by a digest of the kept files' tree entries
  (path and blob id), not the commit: an unrelated commit, or a change to a file the import drops,
  is not a new version. When the newest non-rejected version holds the same digest, the answer is
  `200` with `unchanged: true` and that version.
- **An import never takes over a name.** If the newest non-rejected version came from another
  source, or an agent or an operator wrote it, the import is `409 origin_mismatch`. A name a bundled
  or `FELIX_SKILLS_DIR` skill holds is `409 name_shadows_host_skill`, and so is a name an operator
  upload holds at any key, pinned versions included: where an agent's or operator's save only gets
  `shadows_operator_upload: true`, an import is refused.
- Of two imports racing to one skill, one saves and the other is refused (`409 skill_exists` or
  `409 parent_changed`) rather than stacked on it.

Every version record carries the origin of an import: `origin_source` (canonical),
`origin_ref` (as asked), `origin_commit`, `origin_tree_hash`, `origin_license`, and
`origin_committed_at` — the committer date GitHub reports for the folder, which is provenance only,
since the pusher sets it. Every other version has them `null`. The save is audited as
`skill_draft_saved` with the reason `imported from <source>@<commit>`.

### What is kept

| Kept | Dropped, and listed in `dropped_files` |
|---|---|
| `SKILL.md`; `plugin.json` at the root; `scripts/`, `references/`, `assets/` | `evals/` — a third party's scenarios would count toward the gate as if the tenant wrote them |
| a binary asset under `assets/`, stored as base64 | any other file (examples, tests, a `LICENSE`), dot-files and dot-directories, a binary file outside `assets/`, and text that is not UTF-8 |

A `SKILL.md` description over 1,024 characters is clamped. The caps are the bundle format's, checked
from the tree before any file is downloaded, and past any of them the import is
`422 source_too_large`:

| Cap | Limit |
|---|---|
| Kept files | 200 |
| One file | 5 MiB |
| All kept files | 8 MiB, a binary asset counted as its base64 |
| The repository's tree | GitHub must list it in one call; a truncated tree is refused rather than read in part |

One browse or import has 120 seconds of wall clock for all its GitHub calls, eight at a time;
past it, the request is `502 upstream_error`.

## Review and publish

An import lands in the review queue like any draft. Read it with the library's routes — the version
detail, each file, and `…/preview` for the gate's verdict — then publish or reject it.

**The gate is stricter for imported text.** A version that is an import, or built on one, is
judged as an import whoever saved it:

- an `advisory` security scan blocks it, whatever the tenant's or the deployment's policy says
  about advisories (a `fail` blocks every version);
- only the bundle's own `evals/` scenarios count toward an evaluation requirement, and an import
  drops its `evals/`;
- an agent's edit of one always waits for a person, even under `skill_authoring.mode: publish`;
- a rollback to one passes the same gate.

**Lineage taint.** `lineage_import: true` on a version record marks an import and everything built on
it: an agent's or operator's edit, an edit of that edit, an operator save naming no parent on a
skill whose newest version is tainted, and an agent's save of any file byte-identical to a file of
an import-lineage version anywhere in the tenant (an agent copying imported text under another
name). Nothing clears the mark.

## Imported text in front of the model

When a manifest's catalog offers a live skill of import lineage:

| Where | What happens |
|---|---|
| The system prompt's skill catalog | The skill is listed with `untrusted="true"` under a preamble saying such skills come from third parties. A description carrying the injection markers is withheld; the name is still listed |
| `list_skills` | The item carries `"untrusted": true`; the same description rule applies |
| `activate_skill`, `read_skill_file`, `list_skills` | Their output about that skill is marked as relayed from an untrusted author, and [content screening](/guide/manifest-reference/#speccontent_screening) (`spec.content_screening.enabled`) screens it as it screens an untrusted tool's: markers, the optional scoring model, quarantine or block |

Operator and agent skills are not screened this way. A manifest **without** content screening still
gets a floor for imported text: the free injection markers — no scoring model, no decider — run over
what those three tools relay of an imported skill, and a match is quarantined. The compile logs a
warning and increments `felix_imported_skills_unscreened{manifest_id}`, because markers alone miss a
paraphrase: turn content screening on for agents that use imported skills.

The skill suggester (`spec.skill_suggestion`) gives its decision model each skill's description and
the start of its body to rank on, so imported text can steer which skill is hinted. The hint carries
only the name, and the agent still activates the skill through the screening above.

## The cooldown

`FELIX_SKILL_IMPORT_MIN_AGE_DAYS` (0–365, default `0`) refuses an import of files **this tenant first
saw** fewer than that many days ago: `403 too_recent`, nothing saved, no override. It gives a
compromised upstream commit time to be noticed before anyone pulls it.

- The clock is Felix's own (`skill_import_sighting`), never a commit date: a commit backdated by
  years is still new to Felix.
- "These files" is the digest of the kept files. Any change to a kept file is a new digest with its
  own clock; the same files on another branch, tag or commit share one.
- The first sighting is recorded by every browse that lists the skill and every import attempt —
  including a refused one, and whether the cooldown is on or off. Browse first, import later.
- A tenant can raise its own bar with `PATCH /skill-library/-/policy` `{"import_min_age_days": N}`,
  never lower it below the setting; `GET /skill-library/-/policy` shows the value in force.
- Sightings older than 366 days are pruned by the retention sweep, past the longest cooldown the
  setting allows.

## Allowlist and token

`FELIX_SKILL_IMPORT_SOURCES` is a comma-separated list of `[<tenant>=]github:<owner>[/<repo>[/<path>]]`
entries over canonical sources, globs allowed:

| Entry | Covers |
|---|---|
| `acme=github:acme/*` | every repository of `acme`, for tenant `acme` only |
| `acme=github:acme/skills` | `github:acme/skills` and everything under it (`github:acme/skills/skills/pdf-forms`), for tenant `acme` |
| `github:anthropics/skills` | that repository, for every tenant |
| empty (default) | any GitHub source, for every tenant |

A browse or import naming a source no entry covers for the caller's tenant is `403
source_not_allowed`, before GitHub is called. The tenant is the principal's: an API key with no
`tenant_id`, and an anonymous caller, resolve to `default`, so a `default=` entry grants every such
key — give keys a tenant before binding sources to one.

**Boot refusals.** An entry that is not that shape, or names an invalid tenant id, stops the API at
boot. With `FELIX_SKILL_IMPORT_GITHUB_TOKEN` set, boot also refuses:

- an empty list;
- any entry naming no tenant;
- any entry whose owner is a glob (`github:*`).

Each would let one tenant read whatever the token reads — another org's private repositories
included. The one exception is a single person's box: `FELIX_ENVIRONMENT=development` **and**
`FELIX_AUTH_MODE=none`. The environment alone is not enough, since Compose defaults it to
`development`.

**The token** (`FELIX_SKILL_IMPORT_GITHUB_TOKEN`, optional) reaches private repositories and lifts
GitHub's limit from 60 calls an hour to 5,000; read-only Contents access is all it needs. It is
hydrated from the secrets backend like any other credential (`SKILL_IMPORT_GITHUB_TOKEN`,
`skill_import_github_token` or `felix/skill_import_github_token`), sent only in the `Authorization`
header to `api.github.com` — never in a URL, a log line or a response — and masked wherever the
redaction sinks see it. Without one, a private repository is `404 source_not_found`; a token GitHub
refuses is `502 upstream_error`.

## GitHub call budgets

Every GitHub call — not every request — is charged first to the tenant's hourly budget, then to the
deployment's. Past either, the request is `429 rate_limited`; GitHub's own limit running out is
`502 upstream_rate_limited`, with the reset time in the message.

| Setting | Default | Range | |
|---|---|---|---|
| `FELIX_SKILL_IMPORT_CALLS_PER_HOUR` | `500` | 1–100,000 | One tenant's calls per hour |
| `FELIX_SKILL_IMPORT_CALLS_PER_HOUR_TOTAL` | `4000` | 1–1,000,000 | The whole deployment's, protecting the shared token's own limit |

| Request | GitHub calls |
|---|---|
| Browse of 50 skills | 53: the repository, the branch, the tree and 50 `SKILL.md` heads |
| Import | one per kept file, plus 4 |
| Upstream check without a diff (the listing, the periodic check) | 3 |

A bare branch or tag name is looked up as both, which adds one call to each: 54, files + 5, 4. A
commit id costs extra calls to prove it is on the default branch, and an annotated tag one per hop.
At the defaults, eight tenants spending their whole budget fill the deployment's. The buckets live in Redis
when `FELIX_REDIS_URL` is set. When Redis is unreachable each replica falls back to in-process
buckets, so both budgets multiply by the number of API replicas until it recovers — size `_TOTAL`
for that, or keep Redis up.

## Update checks

An imported skill keeps its origin — source, ref, commit and kept-file digest — on its newest
version, and three routes are built on it. None of them runs at compile time.

| Method | Path | Scope | Success | CLI |
|---|---|---|---|---|
| `GET` | `/skill-library/{name}/-/upstream?ref=` | `skills:read`; `skills:write` with `ref` | `200` | `felix skills diff` |
| `POST` | `/skill-library/{name}/-/update` | `skills:write` | `201`, or `200` unchanged | `felix skills update` |
| `GET` | `/skill-library/-/upstream?refresh=&limit=&cursor=` | `skills:read` | `200` | `felix skills outdated` |

The skill's newest version that was not rejected names the origin. A skill whose newest such
version was not imported is `409 not_imported`; a name the library does not hold is `404 not_found`.
Every route judges the source against the tenant's allowlist **as it is now**: a source the
deployment has since unbound from the tenant is `403 source_not_allowed` before any GitHub call,
whichever ref is named.

### Checking one skill

`GET /skill-library/{name}/-/upstream` re-resolves the stored ref — or `?ref=`, another branch, tag
or commit of the same source — under the same [ref rules](#sources-and-refs) as an import. Checking
the stored ref needs `skills:read`. Naming another ref needs `skills:write`, because it chooses what
the deployment's token fetches and the tenant's budget pays for, as an import does.
The answer is `{name, current, upstream, update_available, min_age_days, diff}`:

| Field | |
|---|---|
| `current` | The newest non-rejected version and its origin: `{version, status, source, ref, commit, tree_hash, live_version}` |
| `upstream` | What the ref names now: `{source, ref, commit, tree_hash, license, committed_at, first_seen_at, eligible_at, eligible}` |
| `update_available` | The kept files' digest at the upstream commit differs from the newest version's |
| `diff` | `{compared_with, files, diff_truncated}` against the live version, or the newest when nothing is live |

Each item of `files` is `{path, change, binary, old_size, new_size, diff, truncated}`, with `change`
`added`, `removed` or `modified`; unchanged files are left out. Only changed files are fetched — a
stored file's git blob id is computed from its bytes and compared with the tree's — and only text:
a binary asset is reported by size, never diffed. A fetched file is compared as an import would save
it (a long description clamped, non-UTF-8 text absent). Two bounds apply:

| Bound | Limit | Past it |
|---|---|---|
| The answer | 16,384 characters of diff per file, 131,072 in total | A file's diff is cut at a line boundary (`truncated`); past the total, a file is listed without a diff and not fetched (`diff_truncated`) |
| The work | Either side of a file over 256 KiB (262,144 bytes), or 4,000 lines or more | The file is never diffed: listed by size with `truncated` set, and when the upstream side is the large one, never fetched |

The second bound exists because the diff reads both whole sides before anything is cut; the diff
also runs off the event loop. The diff is third-party text: it is secret-redacted as a file read is,
and `felix skills diff` strips control and invisible characters from it line by line. A skill over the import [caps](#what-is-kept) is
`422 source_too_large` rather than summarised.

**Asking starts the clock.** A check stamps the sighting of what it finds, as a browse does, so an
operator who sees an update today can take it once the cooldown has run from today. A check of the
stored ref is also recorded for the listing; a check with another `?ref=` is a what-if and is not.
A check under `skills:read` spends the tenant's GitHub budget and stamps sightings as a browse
does; that is intended, and the budget is what bounds it. A single check costs the three calls
above, one more for the folder's commit date, and one per changed text file it reads.

### Updating

`POST /skill-library/{name}/-/update`, with an optional body `{ref}`, is the import itself from the
stored origin: a new draft (`201`), `200` with `unchanged: true`, `403 too_recent` inside the
cooldown, `409 origin_mismatch` — the stricter gate and the lineage taint all as above. There is no
`publish` field; a person publishes the draft after review. The answer is an import's plus `diff`:
the saved draft against the live version, else the version it was built on, read from the library
without a GitHub call. The draft's `skill_draft_saved` event carries the reason
`updated from <source>@<commit>`. An update with `ref` saves that ref as the new version's
`origin_ref`, so later checks follow it.

### Listing every imported skill

`GET /skill-library/-/upstream` lists the tenant's imported skills by name, each against its origin,
without diffs: `{items, next_cursor, refreshed, min_age_days, stopped}`. Each item is `{name, version,
live_version, origin_source, origin_ref, origin_commit, upstream_commit, upstream_tree_hash,
update_available, first_seen_at, eligible_at, eligible, checked_at, error}`; `error` is the refusal
code of the last check when it failed, with the upstream fields from the last good one. `limit` is
1–25, default 25; follow `next_cursor` until it is `null` (`422 invalid_cursor` for one the route did
not issue).

| `refresh` | Does |
|---|---|
| `true` (default) | Checks each skill now and records it. A repository and ref shared by several skills is resolved once. No check starts 30 seconds after the first (`stopped: deadline`); a budget spent part way ends the page there (`stopped: rate_limited`), with `next_cursor` at the first skill not checked; a budget spent before the first check is `429 rate_limited` |
| `false` | Reads the last recorded checks and calls GitHub not at all |

The library detail, `GET /skill-library/{name}`, carries the same recorded state as `upstream` for an
imported skill (`null` for any other), and never asks GitHub. Imports, updates, checks of the stored
ref, the listing and the periodic check all write that record (`skill_upstream`).

### Periodic checks

`FELIX_SKILL_IMPORT_CHECK_HOURS` (0–168, default `0` = off) has the worker check every imported
skill on that cadence, so the cooldown clock of an update starts without anyone asking and the
listing's `refresh=false` stays current.

- The worker's `skill_upstream_checks` task runs every ten minutes and tries up to 50 skills whose
  last check is at least that many hours old, never-checked first, then the oldest check, across
  every tenant. Within a tick, one tenant's skills from one repository and ref resolve once. One sweep runs at
  a time across workers, held by its own `skill_job_lease` row. It needs `felix-scheduler`.
- It charges the same tenant and deployment buckets as people do, but stops at **half** of each, so
  the rest of the hour stays for people asking. It is fair across tenants: a tenant past its half is
  left out of the rest of the tick and the due skills are read again without it, so one tenant's
  backlog cannot fill the batch and leave every other tenant unchecked. The deployment's half, or
  GitHub's own rate limit on the shared token, ends the tick. It shares the API's buckets only through Redis (`FELIX_REDIS_URL`); a worker without Redis spends
  a budget of its own.
- A refused check records its code as `error` and keeps the last good state. A folder past the
  import caps is recorded as `source_too_large` rather than offered as an update no import could
  take. A skill whose newest version is no longer an import is recorded as `not_imported`, and
  checked again once it is one.
- **The sweep runs on the worker's environment.** Give the worker the same
  `FELIX_SKILL_IMPORT_SOURCES` and `FELIX_SKILL_IMPORT_GITHUB_TOKEN` as the API, or it judges
  origins against another allowlist and reads GitHub with another token, or none. With
  `FELIX_SKILL_IMPORT_CHECK_HOURS` set, `felix doctor` prints a note saying so, plus one when this
  process has no allowlist (checks re-resolve any stored origin) or no token (anonymous, 60 calls an
  hour for the whole server, private origins not found). Doctor can only see the process it runs
  in, so run it on both.
- An update the sweep finds shows on the listing and the detail, and is announced to the tenant's
  webhook only when `FELIX_SKILL_UPDATE_WEBHOOKS` binds one: see
  [Update notifications](#update-notifications).

### Update notifications

`FELIX_SKILL_UPDATE_WEBHOOKS` announces an imported skill's new upstream content to an endpoint the
operator registered in `FELIX_WEBHOOK_ENDPOINTS` — the
[completion-webhook](/guide/deploy/#completion-webhooks) registry — as one signed
`skill.update_available` event per new digest. It is off by default, and a tenant it does not name
gets nothing.

```bash
FELIX_SKILL_UPDATE_WEBHOOKS=acme=ops,acme=ci,beta=beta-hook
```

The value is comma-separated `tenant=endpoint_id`, a tenant named once per endpoint. Each id must be
a `FELIX_WEBHOOK_ENDPOINTS` endpoint whose `tenants` include that tenant (a list naming it, or
`"*"`). There is no wildcard on either side, so one tenant's skill names and sources never reach an
endpoint bound only to another. The process refuses to boot on:

| Value | Boot error |
|---|---|
| An entry without `=`, or with either side empty | `FELIX_SKILL_UPDATE_WEBHOOKS: entry '<entry>' must be tenant=endpoint_id` |
| `*` as the tenant, or in the endpoint id | `FELIX_SKILL_UPDATE_WEBHOOKS: entry '<entry>': there is no wildcard; bind each tenant to its endpoint` |
| An id `FELIX_WEBHOOK_ENDPOINTS` does not hold, or whose `tenants` leave this tenant out | `FELIX_SKILL_UPDATE_WEBHOOKS: <tenant>=<id>: no FELIX_WEBHOOK_ENDPOINTS endpoint '<id>' registered for '<tenant>'` |
| A tenant that is not a usable tenant id | `FELIX_SKILL_UPDATE_WEBHOOKS (<tenant>) is not a usable tenant id: …` |

Checks run on the API (a check of one skill, the listing) and on the worker (the periodic sweep),
and only the worker delivers, so give both the same `FELIX_SKILL_UPDATE_WEBHOOKS` and
`FELIX_WEBHOOK_ENDPOINTS`. Both are read again at send time: an endpoint unbound from the tenant,
removed from the registry, or no longer open to the tenant goes `dead` for that event without a
request.

**When an event is queued.** Only a **recorded** check queues one: the periodic sweep, a check of
the stored ref (`GET /skill-library/{name}/-/upstream` without `ref`), and the listing with
`refresh=true`. It queues when the kept-file digest it finds is not the skill's newest version's
and not the digest already queued for that skill — once per digest — and a check older than the one
that queued what is there replaces nothing.

- A `?ref=` check is a what-if: it is never recorded, so it never notifies.
- An import or update records the digest it imported and never queues, since that digest is the
  newest version's own. It can only supersede an event queued before it.
- Queuing is all a check does. The worker's `skill_update_notifications` task sends the event, so
  no check, listing or import waits on a receiver or fails because of one.
- An event changes nothing on its own: it does not import, publish, or start a cooldown the check
  had not already started.

Each queued event is audited as `skill_update_notification_queued`.

**Superseded.** An event that is no longer news is marked `superseded` and never sent:

- a newer digest is found before it was delivered, and replaces it; a delivery of the older one
  that finishes after that cannot overwrite the newer one;
- the origin has moved on from its digest, or the skill's newest version already holds it (someone
  imported it). This is checked before every delivery, and by every recorded check that finds the
  newest version current.

A superseded digest that the origin returns to is queued again as a new event: A, then B, then A is
three events.

**The payload** is metadata only — never a file, a diff or a description, because upstream text is
untrusted and the body leaves the deployment:

```json
{
  "type": "skill.update_available",
  "tenant_id": "acme",
  "skill": "pdf-tools",
  "source": "github:acme/skills/pdf-tools",
  "ref": "main",
  "current": {"version": "1.2.0", "commit": "9f2c…", "tree_hash": "4b1e…"},
  "upstream": {
    "commit": "c07a…",
    "tree_hash": "e81d…",
    "committed_at": 1790000000000,
    "first_seen_at": 1790000500000
  },
  "eligible_at": 1790605300000,
  "checked_at": 1790000500000,
  "changed_files": 2
}
```

| Field | |
|---|---|
| `type` | Always `skill.update_available` |
| `tenant_id`, `skill` | Whose skill, by library name |
| `source`, `ref` | The stored origin's canonical source and ref |
| `current` | The skill's newest non-rejected version and the origin commit and digest it holds |
| `upstream.commit`, `upstream.tree_hash` | What the ref names now |
| `upstream.committed_at` | The commit date GitHub reports, epoch ms; `null` unless a check of one skill read it. Provenance only — the pusher sets it |
| `upstream.first_seen_at` | When this tenant first saw these files, epoch ms: the [cooldown](#the-cooldown)'s clock |
| `eligible_at` | When the cooldown lets an import take them, epoch ms; equal to `first_seen_at` with no cooldown |
| `checked_at` | When the check that queued it ran, epoch ms |
| `changed_files` | Present only when a check of one skill diffed the upstream files against the newest version: how many files differ |

The body is compact, key-sorted JSON, built once when the event is queued, so every retry sends the
same bytes.

**Signing and dedupe.** Delivery is the completion webhooks' own: the same
[Standard Webhooks](/guide/rest-api/#completion-webhooks) headers and signature, egress guard,
`user-agent: Felix-Webhooks/1`, and secret. `webhook-id` is `skill_update_` plus 32 hex characters
of a SHA-256 over the tenant, skill name, digest and the row's queue generation. It is the same on
every retry of one event and on every endpoint it goes to, and new each time the skill queues one —
so **dedupe on `webhook-id`**, not on the skill and digest, or the A, B, A case above loses its
third event. `webhook-timestamp` is the time of each attempt, so the signature differs between
retries of the same body.

**Shared receivers.** Run and skill events can arrive at one endpoint under one secret, so a
receiver **dispatches on `type`** (`run.*` or `skill.update_available`), never on the body's shape.
An endpoint bound to several tenants (`acme=ops,beta=ops`) receives all of their events, told apart
only by `tenant_id`.

**Retries and dead letters.** A non-2xx answer, a redirect, a transport error or no answer within
`FELIX_WEBHOOK_TIMEOUT_SECONDS` is a failed attempt, retried after 1m, 2m, 4m … up to 1h, and that
endpoint goes `dead` after `FELIX_WEBHOOK_MAX_ATTEMPTS` (8). The event is `delivered` when every
endpoint took it, `dead` when none is left pending and any did not. The state lives on the skill's
`skill_upstream` row, which no route returns: watch
`felix_webhook_delivery{kind="skill_update", outcome="dead"}`.

**Fairness.** The `skill_update_notifications` task runs every minute, one sweep at a time across
workers (its own `skill_job_lease` row). Each tick claims at most 50 due events, earliest due first,
and **at most 10 of one tenant's**, so one tenant's backlog or slow receiver cannot hold every other
tenant's events behind it. Each claim lasts 120 seconds, so a sweep that dies mid-batch leaves its
events to the next; no endpoint is tried after the first 60 seconds of a tick, and what is left
stays pending for the next. It needs `felix-scheduler`.

| Metric | |
|---|---|
| `felix_skill_update_notification{outcome}` | `enqueued` when a check queues an event; `superseded` when one is never sent |
| `felix_webhook_delivery{kind="skill_update", endpoint, outcome}` | Each attempt: `delivered`, `retry` or `dead` |

## CLI

`felix skills` talks to a running server; the server does the fetching, within its allowlist, so the
CLI never reaches GitHub itself. Every string that came from a repository is stripped of control
characters, bidi overrides and invisible characters before it reaches the terminal.

| Command | Route | |
|---|---|---|
| `felix skills browse <source> [--ref]` | `GET /-/browse` | One line per skill: source, name, description, and `(too recent to import until <date>)` inside the cooldown |
| `felix skills add <source> [--ref]` | `POST /-/import` | Saves a draft and prints the dropped files and the routes to preview and publish it; says so when nothing changed |

Every command takes `--url` and `--api-key`. A refusal prints `<error>: <message>` on stderr and
exits `1`. The Python client has the same calls: `FelixClient.browse_skills(source, ref=)` and
`import_skill(source, ref=)`.

## Errors

Every refusal is `{error, message}`. A body or query that fails validation (an unknown field, a
source over 512 characters) is FastAPI's `422` with `detail`.
